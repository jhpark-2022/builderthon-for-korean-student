# 배경 입자를 싱가포르(왼쪽)와 서울(오른쪽) 형상으로

Claude Code용. `docs/background-crossing-field-brief.md`로 만든 "건너는 점들" 배경(`variant="crossing"`) 위에 얹는 후속 작업이다. 국면, 등불, 강 반사 띠, 품질 티어는 그대로 두고 **기슭 두 곳의 입자 초기 분포만** 형상으로 바꾼다.

---

## 0. 한 줄 목표

히어로에서 왼쪽 기슭의 입자는 **싱가포르 본섬** 윤곽으로, 오른쪽 기슭의 입자는 **서울특별시 경계** 윤곽으로 서 있다가, 스크롤하면 지금처럼 강을 건너 등불로 모인다. 형상은 첫 화면에서 한눈에 읽혀야 하고, 건너기 시작하면 흩어져도 된다.

## 1. 형상 원본

- **싱가포르**: 로고 심볼의 섬 패스를 그대로 쓴다. `public/naru/naru-symbol.svg`(또는 원본 `12월 빌더톤/그룹 기획/나루_로고_확정/SVG/naru_07_심볼만.svg`). 로고와 같은 단순화 정도라 브랜드와 어긋나지 않는다. 남쪽 해안의 주황 점은 **가져오지 않는다**(화면의 주황은 등불 하나뿐).
- **서울**: 서울특별시 행정 경계 GeoJSON을 받아 Douglas-Peucker로 60~90 꼭짓점까지 단순화한다. 출처는 공공데이터(통계청 행정구역 경계, 국토지리정보원) 또는 그것을 정리한 공개 저장소(예: GitHub `southkorea/seoul-maps`의 시 경계). 받은 파일의 라이선스와 출처를 `lib/background/shapes/README.md`에 적는다. **손으로 그리지 않는다.** 한강은 같은 출처에 하천 폴리곤이 바로 있을 때만 빈 띠로 뚫고, 없으면 생략한다(지어낸 강은 넣지 않는다).
- 두 형상 모두 북쪽이 위. 좌우 반전 금지. 실제 크기 비율(싱가포르 동서 약 50km, 서울 약 37km)은 무시하고 **화면에서 같은 너비**로 맞춘다. 둘이 나란히 같은 무게로 서야 한다(어느 쪽이 주인공이 아니다).

## 2. 점 샘플링 (빌드 타임)

`scripts/build-shape-points.py` 하나로 두 형상을 점 집합으로 굽는다. 런타임에 SVG를 파싱하지 않는다.

- 각 형상을 512×512 캔버스에 래스터라이즈 → 안쪽에서 점을 뽑는다. **가장자리 가중**: 윤곽에서 안쪽 6% 이내는 밀도 3배, 그 안쪽은 1배. 윤곽이 읽히는 것은 테두리이고, 속은 성기게 있어야 "섬"이지 "덩어리"가 아니다.
- 점 사이 최소 거리(푸아송 디스크)로 뭉침을 막는다.
- 형상당 2,000점을 굽고, 런타임에 품질 티어의 입자 수 절반(`particles / 2`)만큼 앞에서부터 쓴다. 굽는 순서를 **가장자리 먼저, 그다음 안쪽**으로 섞어 두면 폰의 450점으로도 윤곽이 남는다.
- 출력은 `lib/background/shapes/singapore.ts`, `seoul.ts`에 `Float32Array`(xy 정규화, 형상 바운딩 박스를 [-1,1]에 맞춤)로 base64 또는 숫자 리터럴. fetch 없음.
- 스크립트는 레포에 남기고(`scripts/` 관행), 실행 명령과 입력 파일 경로를 파일 머리에 적는다.

## 3. 장면 배치

- `ParticleField`의 crossing 초기화에서 기슭 분포(이봉 가우시안)를 형상 점으로 교체한다. 각 점에 z 깊이는 얕은 두께(±0.15)로 흩어 주고, 전체를 **지도가 탁자 위에 놓인 것처럼 약 18° 눕힌다**(x축 회전). 그래야 3° 포인터 패럴랙스에서 입체가 살면서도 위에서 본 윤곽으로 읽힌다. 25°를 넘기면 서울이 납작해져 못 알아본다.
- 위치: 뷰포트 기준 싱가포르 중심 x 22%, 서울 중심 x 78%, y는 둘 다 55% 근처(히어로 텍스트 아래쪽). 각 형상의 너비는 뷰포트 너비의 22~26%. 히어로 카피(왼쪽 단)와 겹치는 영역에서는 입자 밝기를 40%로 눌러 글자 대비를 지킨다(9/15의 히어로 뒤 휘도 기준 유지).
- 세로 화면(폰): 좌우로 두면 각 형상이 너무 작다. **위아래로 쌓는다**. 싱가포르 위(y 35%), 서울 아래(y 70%), 너비는 뷰포트의 55%. 이때 강은 가로 띠가 아니라 둘 사이의 어두운 간격이고, 반사 띠는 그 사이에 얇게.
- 라벨: 각 형상 아래에 작은 대문자 자간 라벨 `SINGAPORE` / `SEOUL`(로고 링의 글자 문법, `text-white/40`, 11px). 서울 경계는 섬만큼 누구나 아는 윤곽이 아니라서 라벨이 있어야 읽힌다. DOM 텍스트로 두고(캔버스에 그리지 않음) `banks` 국면에서만 보이다가 `gather`에서 사라진다. `{ ko, en }`으로 두되 두 로케일 모두 영문 표기.

## 4. 국면과의 연결

- `banks`(0~0.15): 형상 그대로. 입자는 제자리에서 아주 작게 숨 쉰다(진폭은 지금의 30%). 형상이 흐트러지면 안 된다.
- `gather`(0.15~0.45): 형상이 풀린다. 가장자리 점부터 강가로 끌린다(안쪽 점은 늦게). 윤곽이 먼저 사라지고 속이 남는 것보다, **윤곽이 마지막까지 남는 쪽**이 읽기 좋다. 그러니 순서를 뒤집어 안쪽 점부터 움직이고 가장자리 점이 마지막에 떠난다.
- `crossing` 이후: 지금 구현 그대로.
- 등불 위치는 지금 그대로(강 가운데, 건너편). 서울 형상 위로 옮기지 않는다. 나루는 두 기슭 사이의 자리이지 어느 도시가 아니다.
- 정지 토글(`motionScale` 0)에서는 `banks` 상태로 얼어붙는다. 정지 화면이 곧 형상 두 개다.

- 국면 곡선, 등불, 블룸 임계값, 품질 티어 변경.
