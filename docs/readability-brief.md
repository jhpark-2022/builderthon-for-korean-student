# 가독성 브리프: 글자 뒤를 고요하게, 정렬과 라벨을 하나로

대상 레포: `website` (커밋 `2fcec01` 기준). 바꾸는 곳은 홈(`/`)의 `components/home/NaruHome.tsx`, `components/home/RecordTabs.tsx`, `data/naru.ts`(5장만), 필요하면 `lib/background/`(3장만). `/2026-08`, `/quiz`, 등록 라우트, 수파베이스는 건드리지 않습니다. 체인지로그는 `CLAUDE.md` 규칙대로 `CHANGELOG.md` 맨 위에 씁니다.

## 0. 결론 한 줄

12월 홈이 8월 페이지보다 읽기 어려운 이유는 글자가 아니라 **글자 뒤**입니다. 본문 기둥 뒤에 흐림을 준 반투명 판을 깔아 글자 크기의 점 잡음을 지우고, 정렬과 라벨을 한 규칙으로 맞추고, 추상적인 문장 옆에 구체적인 한 줄을 붙입니다.

## 1. 실측 (배포본, 2026-09-25)

| 항목 | 12월 홈 | 8월 `/2026-08` |
| --- | --- | --- |
| 본문 글자 크기(중앙) | 15.8px | 13.5px |
| 본문 대비(중앙, 남색 위) | 10.3:1 | 9.2:1 |
| **글자 뒤 배경의 잔점**(폰, 화면당 중앙) | **3,327** | **201** |
| 배경 밝기 표준편차(폰) | 13.0 | 7.3 |
| 가운데 정렬 글의 비율(데스크톱) | 42% | 27% |
| 자간 0.12em 이상인 한글 라벨 | 17곳 | 드묾 |

글자 크기와 대비는 12월이 오히려 낫습니다. 차이는 둘입니다. **서울/싱가포르 점 윤곽이 본문 한가운데 뒤에 있고, 점 하나가 글자 획과 크기가 같아서 글자에 섞입니다**(잔점 16배). 그리고 9월 20일 표현 방식 브리프로 상자를 걷으면서 글이 그 배경 위에 그대로 떠 있게 됐습니다. 8월 페이지는 배경이 거의 균일해서 상자 없이도 읽힙니다.

## 2. 읽기 판 (P0)

### 2.1 무엇인가

챕터마다 본문 기둥 뒤에 **판 하나**를 깝니다. 카드가 아닙니다. 테두리도 모서리 반경도 없고, 가장자리가 부드럽게 사라지는 옅은 막입니다. 9월 20일 브리프의 "상자를 쓰는 자리 셋" 규칙과 충돌하지 않습니다. 그 규칙은 내용을 담는 상자이고, 이 판은 배경을 가라앉히는 막이라 보이는 모양이 없습니다.

```tsx
// DECIDED 2026-09-25 (가독성 브리프 2): 읽기 판. 카드가 아니라 배경을 가라앉히는 막입니다.
// 흐림(blur)이 요점입니다. 글자 크기의 점 잡음은 지우고, 형상의 빛과 색과 움직임은 남깁니다.
// 투명도만 올리면 배경이 꺼지고, 흐림만 주면 밝은 점이 번져 남습니다. 둘을 같이 씁니다.
<div aria-hidden className="reading-plate" />
```

```css
.reading-plate {
  position: absolute; inset: -48px -32px;   /* 본문 기둥보다 조금 넓게 */
  z-index: -1; pointer-events: none;
  background: rgba(7, 11, 31, 0.62);
  backdrop-filter: blur(6px); -webkit-backdrop-filter: blur(6px);
  /* 네 가장자리를 부드럽게. 판의 경계가 선으로 보이면 안 됩니다. */
  mask-image: linear-gradient(to bottom, transparent, #000 64px, #000 calc(100% - 64px), transparent),
              linear-gradient(to right, transparent, #000 40px, #000 calc(100% - 40px), transparent);
  mask-composite: intersect; -webkit-mask-composite: source-in;
}
@media (max-width: 639px) { .reading-plate { inset: -40px 0; background: rgba(7, 11, 31, 0.55); backdrop-filter: blur(4px); } }
@supports not (backdrop-filter: blur(1px)) { .reading-plate { background: rgba(7, 11, 31, 0.82); } }
@media (prefers-reduced-transparency: reduce) { .reading-plate { background: rgba(7, 11, 31, 0.9); backdrop-filter: none; } }
```

### 2.2 어디에

`#december`, `#gains`, `#naru`(`#record` 포함), `#join` 네 챕터의 본문 기둥 각각에 하나씩, 최대 네 개. 히어로와 푸터에는 두지 않습니다. 챕터 제목(알약 라벨 + h2)도 판 안에 들어갑니다.

- 판 안에 판을 두지 않습니다. 판 안의 기존 상자(규칙 ①②③에 해당하는 것)는 그대로입니다.
- 데스크톱에서 판 양옆으로 형상이 보이는 것은 의도입니다. 배경을 끄는 작업이 아닙니다.

### 2.3 성능

`backdrop-filter`는 움직이는 캔버스 위에서 비쌉니다. 배경 품질 단계(`pickQuality`)가 가장 낮은 기기에서는 흐림을 빼고 `rgba(7, 11, 31, 0.8)`만 씁니다. 판 네 개가 동시에 화면에 걸리는 일은 없습니다(챕터가 한 화면보다 깁니다).

## 3. 형상을 본문 기둥에서 비킴 (조건부)

2장을 적용한 뒤 5장 검증 1을 잽니다. **통과하면 이 장은 하지 않습니다.**

통과하지 못하면 `particles` 셰이더에서, 화면 가로 위치가 본문 기둥 안(데스크톱은 기둥 폭 ± 24px, 폰은 전체)에 있는 점의 밝기에 0.5를 곱합니다. 기둥 폭은 `BackgroundScene`이 `#december` 본문 기둥의 `getBoundingClientRect()`로 읽어 유니폼으로 넘깁니다. 형상의 모양, 위치, 점 크기, 구간 지도는 바꾸지 않습니다.

## 4. 정렬과 라벨 (P1)

### 4.1 정렬

- **가운데 정렬은 챕터 머리(알약 라벨 + h2 + 바로 아래 리드 한 문단)와 히어로, 푸터에만** 씁니다. 8월 페이지의 섹션 머리와 같은 규칙입니다.
- 그 아래는 전부 왼쪽 정렬입니다. 본문, 목록, 버튼 줄, "담을 쌓는 모임이 아닙니다" 같은 `#join`의 문단, "절박하지 않아도 시작할 수 있도록." 블록, 매니페스토 링크 줄까지.
- 버튼은 속한 글의 왼쪽 끝에 맞춥니다. 폰에서 버튼 여럿은 세로로 쌓고 왼쪽 정렬입니다.

### 4.2 라벨

지금 라벨이 세 종류로 섞여 있습니다. 둘로 줄입니다.

| 종류 | 예 | 새 모양 |
| --- | --- | --- |
| 챕터 라벨 | 참가 혜택, 변하지 않는 두 개, 왜 이 그룹인가 | 지금의 알약 그대로 |
| 챕터 안 소제목 | 일정, 이렇게 굴립니다, 학생이 도전할 수 있는 AI 활용 범위, 8월에 아쉬웠던 넷, 끝나면 할 일, 세 층 | **16px, font-semibold, white/85, 자간 0**. 작은 회색 대문자식 라벨을 쓰지 않습니다 |
| 누르는 것 | 그래서 지키는 것 ⌄ | 규칙 ①의 버튼 모양(알약 테두리) |

- **한글에 자간 0.08em 이상을 쓰지 않습니다.** 라틴 대문자(DAY 0, SGT 등)만 넓은 자간을 유지합니다.
- 세션, 공간, 제출, 기록 같은 표의 행 라벨은 13px 이상, white/60 이상.
- `DECIDED 2026-09-25` 주석으로 이 두 규칙을 `NaruHome.tsx` 머리에 남깁니다.

## 5. 추상적인 문장 옆에 구체적인 한 줄 (P2, 사용자 승인 뒤 커밋)

뜻이 한 번에 잡히지 않는 선언형 문장 옆에 **사이트에 이미 있는 사실만으로** 한 줄을 붙입니다. 새 사실을 만들지 않습니다. 날짜는 `lib/naruDates.ts`의 값을 씁니다(일정이 12월 18~22일로 바뀌었으니 하드코딩 금지).

아래는 초안입니다. 이 표 그대로 적용하지 말고, 먼저 **나머지 후보를 찾아 표를 완성해 사용자에게 보여 주고 승인받은 뒤** 커밋합니다.

| 자리 | 지금 | 붙일 한 줄(초안) |
| --- | --- | --- |
| `#december` h2 | 데이터에서 증명까지, 닷새 | {날짜}, 서울. 기업이 준 데이터로 문제를 찾고, 마지막 날 그 기업 앞에서 발표합니다. |
| `#naru` h2 | 건너는 건 각자가 한다. 자리는 우리가 만든다. | 나루는 학생회와 기업을 이어 이벤트를 엽니다. 첫 이벤트는 2026년 8월 싱가포르의 제로백 빌더톤이었습니다. |
| 변하지 않는 두 개 | 우리는 두 가지를 만들려고 모였습니다 | 스크리닝과 순위가 없는 자리, 그리고 실명 기업 앞에서 직접 증명하는 경험입니다. |
| 세 층 | 어떻게 일하는가 | 학생회는 학생과 공간을, 기업은 문제와 자금을, 나루는 회차를 맡습니다. |

- 붙이는 줄은 리드 문단 스타일(본문 크기, white/75)입니다. 새 스타일을 만들지 않습니다.
- 기존 문장은 지우거나 바꾸지 않습니다. 옆에 붙이기만 합니다.
- 영어 카피도 같이 씁니다. 사람 이름, 전사록 인용은 쓰지 않습니다.
