# 히어로 효과 브리프: 보이지 않는 곳에서만 움직이고 있습니다

대상 레포: `website` (커밋 `8cfd328` 기준). 바꾸는 파일은 `components/shared/useHeroRecede.ts`와 `components/home/NaruHome.tsx`의 히어로 부분입니다. 배경, 카피, 다른 챕터는 건드리지 않습니다.

계측 대상: https://naru-crossing-seoul.vercel.app/ (1440×900, 390×844). 실제 휠 스크롤로 110px씩 내리며 각 지점에서 두 블록의 계산된 `transform`과 `opacity`, 그리고 화면 좌표를 읽었습니다.

## 0. 결론 한 줄

코드는 정상 작동합니다. 값도 곡선대로 정확히 나옵니다. **문제는 그 값이 변하는 구간과 그 요소가 화면에 보이는 구간이 거의 겹치지 않는다는 것입니다.** 효과는 헤더 뒤에서, 또는 이미 화면을 벗어난 뒤에 일어나고 있습니다.

## 1. 실측 지오메트리

| | 데스크톱 1440×900 | 폰 390×844 |
| --- | --- | --- |
| 고정 헤더 | 90px | 52px |
| 카피 블록 | 문서 y 90~929 (높이 839) | 문서 y 72~666 (높이 594) |
| 그 안의 제목 | 문서 y 90~290 남짓 | 문서 y 72~250 남짓 |
| CTA 버튼 | 문서 y 636~701 | 문서 y 523~666 |
| 사진 단 | 문서 y 240~779 (높이 539) | 문서 y 702~1155 (높이 453, 카운트다운 포함) |

## 2. 무엇이 어긋나 있나

### 2.1 데스크톱: 제목은 한 번도 페이드되지 않습니다

`copyOpacity`의 구간은 `[vh × 0.25, vh × 0.85]`, 즉 **스크롤 225px에서 765px**입니다.

그런데 제목(문서 90~290)이 90px짜리 고정 헤더 위로 완전히 사라지는 시점은 **스크롤 200px**입니다. 페이드가 시작되기 25px 전에 제목은 이미 없습니다.

| 스크롤 | 불투명도 | 그때 화면에 남아 있는 것 |
| --- | --- | --- |
| 200 | 1.0 | 제목이 막 사라짐. 아무 일도 일어나지 않았음 |
| 500 | 0.49 | CTA 버튼과 카운트다운 패널만 |
| 765 | 0.0 | 카운트다운 패널이 아직 164px 화면에 있는데 완전히 투명 |

즉 이 효과가 실제로 하는 일은 **제목을 페이드하는 것이 아니라, 아직 화면에 있는 카운트다운 패널을 지우는 것**입니다. 의도와 정반대입니다.

### 2.2 데스크톱: 움직임의 폭이 지각 한계 아래입니다

`copyY`는 스크롤 900px 동안 −80px입니다. 같은 구간에 페이지 자체가 900px 올라갑니다. 차이는 **8.9%**이고, 높이 839px짜리 블록에서 80px의 차이는 보이지 않습니다. 사진 단은 −24px, 즉 2.7%입니다.

### 2.3 폰: 처음 440px 동안 아무 일도 일어나지 않습니다

측정값 그대로입니다.

| 스크롤 | 카피 블록 |
| --- | --- |
| 110 · 220 · 330 · 440 | `transform: none`, `opacity: 1` (변화 없음) |
| 550 | `translateY(-7px)`, 0.781 |
| 660 | `translateY(-30.7px)`, 0.04 |
| 770 | `translateY(-32px)`, 0 |

`useHeroExit`의 구간이 진행도 `[0.75, 1]`이라서 그렇습니다. 카피 블록의 진행도 0.75는 **스크롤 518px**이고 1은 666px입니다. 그 148px 동안 화면에 남아 있는 것은 블록의 아래쪽 148px인데, 위 52px은 헤더가 덮습니다. **실제로 보이는 것은 96px짜리 띠 하나이고, 그 띠가 148px 스크롤하는 동안 사라집니다.** 사람 눈에는 아무 일도 없습니다.

### 2.4 폰: 두 번째 블록은 더 늦습니다

카운트다운과 사진이 든 블록(문서 702~1155)의 진행도 0.75는 **스크롤 1,042px**입니다. 그때 보이는 부분은 61px입니다. 측정에서 스크롤 990px까지 이 블록은 `transform: none`, `opacity: 1`이었습니다.

### 2.5 `useHeroExit`는 자기가 움직이는 요소를 재고 있습니다

`useScroll({ target: ref })`의 `ref`가 `y`를 받는 바로 그 `motion.div`에 붙어 있습니다. 요소가 −32px 움직이면 그 요소의 경계 상자도 −32px 움직이고, 진행도가 다시 계산됩니다. 지금은 폭이 작아서 티가 안 나지만 폭을 키우면 바로 드러나는 되먹임입니다.

## 3. 고치는 원칙

값을 키우는 것으로는 해결되지 않습니다. **구간을 요소가 보이는 동안으로 옮겨야 합니다.** 그리고 블록 하나에 불투명도 하나를 거는 방식 자체가 문제입니다. 높이 839px짜리 블록은 위쪽과 아래쪽이 839px 간격으로 화면을 떠나는데, 그 둘에 같은 값을 걸 수 있는 구간은 없습니다.

**그래서 대상을 좁힙니다. 움직이는 것은 제목 묶음(아이브로 + 제목 + 설명)이고, CTA와 카운트다운은 건드리지 않습니다.**

이렇게 하면 사용자가 고른 "깊이"가 그대로 살아납니다. 제목이 먼저 빠르게 물러나고, 사진이 느리게 따라오고, 누를 것은 제자리에 남습니다. 오히려 "읽고 누를 것을 지우지 않는다"는 원래 의도에 더 맞습니다.

### 3.1 합격 기준 두 개

구현한 뒤 이 둘로 재세요. 숫자를 고를 때의 기준이기도 합니다.

1. **불투명도가 0.5를 지나는 순간, 그 요소 높이의 35% 이상이 고정 헤더 아래 화면 안에 있어야 합니다.**
2. **불투명도가 0.3 아래로 내려가는 동안, 그 요소 안에 누를 수 있는 것이 화면에 남아 있으면 안 됩니다.**

지금 코드는 데스크톱에서 1번이 0%(제목 기준), 2번이 위반(카운트다운 패널)입니다.

## 4. 실행

### 4.1 `useHeroExit`를 지웁니다

폰과 데스크톱이 같은 축(페이지 `scrollY`)을 쓰게 합니다. 코드 경로가 하나가 되고 2.5의 되먹임이 사라집니다. 브레이크포인트로 갈리는 것은 **구간과 폭뿐**입니다.

`NaruHome.tsx`에서 `copyExit`, `stackExit`와 그 `ref` 두 개를 지웁니다.

### 4.2 `useHeroRecede`를 다시 씁니다

```ts
// ── 왜 구간을 옮겼나 (DECIDED 2026-09-20, 히어로 효과 수정 브리프) ──────────
// 전 버전은 값이 정확했는데 보이지 않았습니다. 데스크톱 페이드 구간이 스크롤
// 225~765px이었고, 제목(문서 90~290)은 90px 헤더 위로 스크롤 200px에 이미
// 사라집니다. 페이드가 시작되기 전에 페이드할 것이 없었어요. 실제로 페이드된
// 것은 스크롤 765px에 아직 164px 화면에 남아 있던 카운트다운 패널입니다.
// 폰은 더 심해서, 효과 구간(스크롤 518~666px) 동안 보이는 것이 96px짜리
// 띠 하나였습니다. 처음 440px 동안은 measured transform이 none이었습니다.
//
// 그래서 대상을 블록 전체가 아니라 **제목 묶음**으로 좁힙니다. 높이 839px짜리
// 블록은 위와 아래가 839px 간격으로 화면을 떠나서, 둘 다 만족하는 불투명도
// 구간이 존재하지 않습니다. CTA와 카운트다운은 이제 건드리지 않습니다.
// "읽고 누를 것을 지우지 않는다"는 원래 의도가 여기서 더 잘 지켜집니다.
//
// 합격 기준(브리프 3.1): 불투명도 0.5 지점에서 요소 높이의 35% 이상이 헤더
// 아래 화면 안. 불투명도 0.3 아래에서 누를 수 있는 것이 화면에 없을 것.
// 값을 바꾸려면 이 둘을 다시 재세요.
// ─────────────────────────────────────────────────────────────────────────────
export function useHeroRecede() {
  const { scrollY } = useScroll();
  const reduce = useReducedMotion();
  const [vh, setVh] = useState(900);
  const [isWide, setIsWide] = useState(true);   // 데스크톱 우선. 아래 주석 참고.
  useEffect(() => {
    const sync = () => {
      setVh(window.innerHeight);
      setIsWide(window.matchMedia("(min-width: 1024px)").matches);
    };
    sync();
    window.addEventListener("resize", sync);
    return () => window.removeEventListener("resize", sync);
  }, []);

  // 제목 묶음. 데스크톱은 스크롤 300px, 폰은 260px 안에 끝납니다. 둘 다 그
  // 구간 내내 제목이 화면에 있습니다(1장 지오메트리).
  const end = isWide ? 300 : 260;
  const titleY = useTransform(scrollY, [0, end], [0, isWide ? -120 : -60]);
  // 첫 40px은 자리만 옮깁니다. 첫 픽셀에 글자가 옅어지면 고장으로 보입니다.
  const titleOpacity = useTransform(scrollY, [40, end], [1, 0]);

  // 사진 단(데스크톱 오른쪽, 문서 240~779). 아래쪽이 화면을 떠나는 것이 스크롤
  // 689px이라 거기서 끝냅니다. 0이 아니라 0.2에서 멈추는 이유: 0까지 내리면
  // 아직 화면에 있는 동안 사라집니다(합격 기준 2번).
  const photoY = useTransform(scrollY, [0, 700], [0, -48]);
  const photoScale = useTransform(scrollY, [0, 700], [1, 0.92]);
  const photoOpacity = useTransform(scrollY, [200, 700], [1, 0.2]);

  // 폰의 두 번째 블록(카운트다운 + 사진, 문서 702~1155). 아래쪽이 떠나는 것이
  // 스크롤 1,155px입니다. 카운트다운 숫자를 읽는 중에 지우지 않도록 늦게 시작해
  // 0.25에서 멈춥니다.
  const stackY = useTransform(scrollY, [450, 1050], [0, -40]);
  const stackOpacity = useTransform(scrollY, [650, 1100], [1, 0.25]);

  // 페이드는 두 화면 모두. 움직임만 prefers-reduced-motion을 봅니다.
  // 이 설정이 막으려는 것은 움직임이고, 투명도 변화는 움직임의 대체로 권장되는
  // 쪽입니다(전 버전의 판단 그대로).
  const move = !reduce;
  return {
    titleY: move ? titleY : undefined,
    titleOpacity,
    photoY: move ? photoY : undefined,
    photoScale: move ? photoScale : undefined,
    photoOpacity,
    stackY: move ? stackY : undefined,
    stackOpacity,
  };
}
```

`isWide`의 기본값을 `true`로 바꾼 것은 첫 프레임 때문입니다. 지금은 `false`로 시작해서 데스크톱에서도 첫 렌더가 폰 경로를 타고, `useEffect` 뒤에 바뀝니다. 구간이 `isWide`에만 걸려 있으므로 기본값을 데스크톱 쪽에 두면 폰에서 한 프레임 동안 300px 구간을 쓰는데, 그 한 프레임은 스크롤 0이라 값이 같습니다. 반대 방향은 값이 다릅니다.

### 4.3 `NaruHome.tsx`: 제목 묶음을 감쌉니다

카피 단의 `motion.div`에서 `style`을 걷고, 그 안에서 **아이브로부터 설명 문단까지**를 새 `motion.div`로 감쌉니다. CTA와 그 아래(등록 안내, 카운트다운 패널)는 바깥에 둡니다.

```tsx
          {/* 2026-09-20 (히어로 효과 수정 브리프 4.3): 효과의 대상이 카피 단 전체가
              아니라 제목 묶음입니다. 전에는 블록 전체에 걸려서, 제목이 화면을 떠난
              뒤에 CTA와 카운트다운이 지워지고 있었습니다. */}
          <div className="relative text-center lg:pl-10 lg:text-left xl:pl-16">
            <motion.div style={{ y: hero.titleY, opacity: hero.titleOpacity }}>
              <Eyebrow color="purple">{t(naru.eventHero.eyebrow)}</Eyebrow>
              {/* h1, 날짜 줄, 포지션 줄, 설명 문단까지 여기 안에 */}
            </motion.div>
            {/* CTA 둘, 등록 안내, 카운트다운 패널은 여기 바깥. 움직이지 않습니다. */}
          </div>
```

사진 단은 `hero.photoY / photoScale / photoOpacity`로 그대로, 폰의 두 번째 블록은 `hero.stackY / stackOpacity`로 바꿉니다. `ref`는 필요 없습니다.

## 5. 절대 하지 말 것

- **CTA 버튼과 카운트다운 패널에 불투명도를 걸지 마세요.** 이 브리프의 전부입니다.
- `useScroll({ target })`을 쓰지 마세요. 자기가 움직이는 요소를 재게 됩니다(2.5).
- 폰과 데스크톱에 서로 다른 축을 쓰지 마세요. 구간과 폭만 다릅니다.
- `filter: blur()`를 쓰지 마세요. 전 버전의 판단 그대로입니다. `transform`과 `opacity`만 씁니다.
- 8월의 `useHeroSplit`(좌우 ±500px)을 되살리지 마세요. 사용자가 2026-09-19에 걷었습니다.
- 푸터의 배경 정지 토글(`MotionToggle`)을 보지 마세요. 저 손잡이는 배경 캔버스의 것입니다.
- `Chapter`의 리빌(`data-chapter-reveal`, `transition-all duration-700`)을 건드리지 마세요. 히어로 효과와 별개이고 잘 돌아갑니다.
- em dash 금지. 결정은 `DECIDED 2026-09-20` 한국어 주석으로.

## 6. 검증

**실제 휠이나 터치 스크롤로 재세요.** `window.scrollTo`로 점프하면 값이 전혀 갱신되지 않습니다(계측에서 확인: 점프 모드에서는 스크롤 900px까지 `transform: none`, 휠 모드에서는 같은 지점에서 `translateY(-72px)`). 왜 그런지는 이 브리프의 범위가 아니지만, 검증 방법을 틀리면 고친 것도 안 고쳐진 것으로 보입니다.

| # | 항목 | 기준 |
| --- | --- | --- |
| 1 | 데스크톱 제목 | 스크롤 150px에서 제목 묶음의 불투명도가 0.5~0.7 사이이고, 제목이 헤더 아래 화면에 보임 |
| 2 | 합격 기준 1 | 제목 묶음의 불투명도 0.5 지점에서 그 요소 높이의 **35% 이상**이 헤더 아래 화면 안 (데스크톱·폰 각각) |
| 3 | 합격 기준 2 | 불투명도가 0.3 아래인 모든 스크롤 위치에서, 그 요소 안에 화면에 남은 `a`나 `button`이 **0개** |
| 4 | CTA | 스크롤 전 구간에서 CTA 버튼 둘의 계산된 불투명도가 항상 **1** |
| 5 | 카운트다운 | 데스크톱에서 카운트다운 패널의 불투명도가 항상 1. 폰에서는 0.25 아래로 내려가지 않음 |
| 6 | 폰 첫 구간 | 스크롤 110px에서 제목 묶음의 `transform`이 `none`이 **아님** (지금은 440px까지 none) |
| 7 | 움직임 폭 | 데스크톱 제목이 구간 끝에서 −120px, 폰 −60px |
| 8 | 되먹임 | `useScroll({ target })` 사용처 0건 |
| 9 | reduced motion | `prefers-reduced-motion: reduce`에서 `transform`은 전 구간 `none`이고 불투명도는 정상 변화 |
| 10 | 첫 프레임 | 페이지 로드 직후(스크롤 0) 제목의 불투명도가 1이고 `transform`이 `none` 또는 `translateY(0)` |
| 11 | 8월 페이지 | `/2026-08`의 히어로가 적용 전과 픽셀 차이 없음 |
| 12 | em dash | 0건 |

## 7. 사용자가 볼 것

고치고 나면 스크롤 0에서 300px 사이에 제목이 위로 물러나며 사라지고, 오른쪽 사진 넷은 그보다 훨씬 느리게 따라오면서 살짝 작아집니다. CTA 버튼과 카운트다운은 제자리에서 그대로 스크롤됩니다. 그 대비가 사용자가 고른 "깊이"입니다.

지금과 가장 크게 다른 점은 **첫 스크롤부터 눈에 보인다**는 것입니다.
