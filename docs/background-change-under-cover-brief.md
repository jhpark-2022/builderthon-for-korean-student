# 배경 브리프: 형상은 판 뒤에서만 바뀝니다

대상 레포: `website` (커밋 `f468ffb` 기준). 바꾸는 파일은 `lib/background/scene/BackgroundScene.ts`, `lib/background/config.ts`, `components/home/NaruHome.tsx`(판에 `data-plate` 속성 하나). 형상의 모양, 크기, 점, 빛의 움직임, 파문, 읽기 판의 모양은 건드리지 않습니다. 체인지로그는 `CLAUDE.md` 규칙대로.

## 0. 결론 한 줄

형상이 바뀌는 구간(서울 떠오름, 서울→싱가포르, 사라짐)의 앵커를 챕터 위치에서 **"읽기 판이 형상을 다 덮고 있는 스크롤 구간"**으로 옮깁니다. 판과 판 사이의 틈에서는 언제나 완성된 형상(서울, 싱가포르, 또는 없음)만 보입니다.

## 1. 지금 무엇이 보이나

사용자: "화면 중간중간 gap마다 싱가포르나 서울의 shape이 보이는 건 좋음. 그런데 shape이 바뀌는 지점이 보임. gap이 나왔을 때 이미 바뀌어 있고, complete shape만 보였으면."

읽기 판은 챕터마다 하나라 판 사이에 틈이 셋 있습니다(1440×900 실측, 문서 y).

| 틈 | 위치 | 틈이 형상 위를 지나는 스크롤 구간 |
| --- | --- | --- |
| A `#december` → `#gains` | 4,537 ~ 4,657 | 약 3,716 ~ 4,578 |
| B `#gains` → `#naru` | 5,470 ~ 5,644 | 약 4,649 ~ 5,565 |
| C `#naru` → `#join` | 8,953 ~ 9,073 | 약 8,132 ~ 8,994 |

형상이 바뀌는 구간은 챕터 머리에서 `vh` 배수로 앵커되어 있어서, 틈과 겹치는지는 운에 달려 있습니다. 오늘 두 번의 수정이 그것을 보여 줍니다. 건너기를 `#naru − 0.5vh`에서 `#naru − 1.8vh`로 당기자(eccb5b4) 틈 B에서 보이던 건너기가 틈 A로 옮겨 갔습니다(사용자 스크린숏: "오면 무엇이 남는가" 위의 반쯤 바뀐 형상). 사라짐(`#join − 0.6vh`, 0.8vh)은 틈 C와 겹칩니다. **창 크기가 바뀌면 겹치는 틈도 바뀝니다**(사용자 창은 약 1000×560). 숫자를 다시 고르는 것으로는 풀리지 않습니다.

## 2. 규칙

```ts

// 앵커는 챕터 머리가 아니라 판과 형상의 실제 위치에서 계산합니다. 창 크기, 카피 길이가
// 바뀌어도 틈에는 완성된 형상만 보입니다.
```

### 2.1 판 덮개 구간 (cover window)

`readAnchors`에서 판마다 **덮개 구간** `[c0, c1]`을 계산합니다. 스크롤이 이 구간 안에 있으면 판의 불투명한 안쪽(가장자리 흐림 64px을 뺀 영역)이 형상의 화면 상자를 전부 덮습니다.

```ts
// 판의 문서 좌표(가장자리 흐림 F를 뺀 안쪽)
const pTop = plate.top + F, pBot = plate.bottom - F, pL = plate.left + Fx, pR = plate.right - Fx;
// 형상의 화면 상자 = 서울 상자와 싱가포르 상자의 합집합(건너는 동안 점이 둘 사이를 오가므로)
const box = union(seoulBox, singaporeBox);   // {top, bottom, left, right}, 화면 좌표
const coversX = pL <= box.left && pR >= box.right;
const c0 = pTop - box.top;       // 이 스크롤부터 판 위쪽이 형상 위를 덮음
const c1 = pBot - box.bottom;    // 이 스크롤까지 판 아래쪽이 형상 아래를 덮음
// coversX가 거짓이거나 c1 <= c0이면 이 판은 덮개가 아닙니다.
```

- `F`는 CSS의 흐림 가장자리(지금 64px), `Fx`는 좌우 흐림(데스크톱 40px, 폰 0). 값은 `config.ts`에 `PLATE_FEATHER = { y: 64, x: 40, xPhone: 0 }`로 두고 CSS 주석과 서로 가리키게 합니다.
- 형상 상자는 `placeSeoul`이 쓰는 값(중심, 폭, 형상의 가로세로 비)으로 계산합니다. 서울과 싱가포르의 실제 점 범위(구운 점의 min/max)를 쓰세요. 추정 비율을 쓰지 않습니다.
- 판을 찾기 위해 `NaruHome.tsx`의 판에 `data-plate="december|gains|naru|join"`을 붙입니다.
- 창 크기, 폰트 로딩, 카피 변화에 따라 다시 계산합니다(지금 `readAnchors`가 불리는 자리 그대로).

### 2.2 구간 배정

| 바뀌는 일 | 어느 판 아래서 | 앵커 |
| --- | --- | --- |
| 해가 내려감(구간 1) | 그대로 | 지금 식 그대로(`#top` 하단 + 1.2vh). 이 장의 대상 아님 |
| 서울 떠오름 | `december` 판 | 시작 = max(`descendEnd`, c0), 길이 = min(`revealVh`, c1 − 시작) |
| 서울 → 싱가포르 | `naru` 판 | 시작 = c0 + 0.05vh, 길이 = min(`morph.spanVh`, c1 − 시작) |
| 형상 사라짐 | `join` 판 | 끝 = c1 − 0.05vh, 시작 = max(c0, 끝 − `dissolve.spanVh`) |

결과로 틈에서 보이는 것:

| 틈 | 보이는 형상 |
| --- | --- |
| A (`#december`→`#gains`) | 완성된 서울 |
| B (`#gains`→`#naru`) | 완성된 서울 |
| C (`#naru`→`#join`) | 완성된 싱가포르 |
| `#join` 판 뒤(푸터 쪽) | 없음(나루 빛만) |

- 건너기를 `#gains` 판 아래에 두지 않는 이유: 데스크톱에서 그 판은 813px이고 서울 상자는 614px라 덮개 구간이 약 70px뿐입니다. `naru` 판(3,300px)은 넉넉합니다.
- `config.ts`: `morph`에서 `startVh`를 지우고 `spanVh: 1.2`로 둡니다. `dissolve`에서 `startVh`를 지우고 `spanVh: 0.8`은 그대로. 새 값 `coverMarginVh: 0.05`.
- `s2`(나루 빛이 가운데로 오르는 진행)와 `s4`(싱가포르에서 빛이 도는 진행)는 새 `morphStart`, `morphEnd`를 그대로 따릅니다. 식은 바꾸지 않습니다.

### 2.3 모자랄 때

덮개 구간이 배정할 길이보다 짧으면(아주 작은 창, 카피가 크게 줄었을 때) 길이를 구간에 맞춰 줄이되 **0.3vh 아래로는 줄이지 않고**, 개발 빌드에서 `console.warn`을 한 번 찍습니다. 덮개 구간이 아예 없으면 지금 식(챕터 머리 앵커)으로 돌아가고 경고합니다.

## 3. 건드리지 말 것

형상의 폭, 점 크기, 밝기, 점 개수, 빛의 가로 이동(`LIGHT_*`), 파문(`RING`, `ringGain`, `reach`), 해가 내려가는 구간 1, 푸터 앞의 빛 거두기(`closingTop − 1.4vh`), 읽기 판의 CSS 모양, 카피. em dash 금지.

## 4. 검증

개발 빌드의 `window.__naruBg`에 `reveal`, `morph`, `dissolve`, `shapeBox`, `plates`(덮개 구간 포함)를 더해 값으로 잽니다.

| # | 항목 | 기준 |
| --- | --- | --- |
| 1 | 틈에서 완성형 | 1440×900, 1280×800, **1000×560**, 390×844 각각에서 문서 전체를 40px 간격으로 훑습니다. 형상 상자가 판의 안쪽 밖에 한 픽셀이라도 걸리는 모든 위치에서 `reveal`, `morph`, `dissolve`가 각각 0 또는 1(오차 0.001). **위반 0곳** |
| 2 | 틈의 모습 | 네 크기 각각, 틈 A, B, C의 한가운데에서 스크린숏. A, B는 완성된 서울, C는 완성된 싱가포르 |
| 3 | 건너기는 일어남 | `naru` 판 덮개 구간 안에서 `morph`가 0에서 1까지 가는 것(길이 0.3vh 이상) |
| 4 | 경고 | 네 크기에서 2.3의 경고가 한 번도 찍히지 않음. `descendVh`를 3.5로 임시로 올려 떠오름 구간을 밀면 경고가 찍힘 |
| 5 | 창 크기 변경 | 1440×900에서 연 뒤 1000×560으로 줄여도 1이 성립(다시 계산됨) |
| 6 | 나머지 불변 | 해가 내려가는 구간, 빛의 움직임, 파문이 적용 전과 같음(같은 스크롤 위치의 `s1`, `lightDx`, `uRingPhase` 비교) |
