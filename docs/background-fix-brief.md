# 배경 WebGL 수정 브리프: 형상을 첫 화면 한가운데로, 배경을 다시 살아 있게

## 1. 결정

### 1.1 형상은 히어로 오른쪽 단의 시각물이다

- 히어로 그리드는 그대로 두 단(왼쪽 카피, 오른쪽). **오른쪽 단 전체가 형상의 무대**가 된다. 무대의 세로 중심 = 히어로의 세로 중심 = 첫 화면의 세로 중심. `data-shape-anchor="stage"` 하나로 바꾸고, `band`·`copy`·`panel` 앵커와 히어로 아래 띠(`lg:h-[min(20vw,24vh)]`, 폰 150px)는 **지운다**. 페이지가 그만큼 짧아진다.
- 무대 안 배치: 싱가포르 왼쪽, 서울 오른쪽, 사이에 강(빈 간격)과 등불. 각 형상 너비 = 무대 너비의 40%, 둘 사이 간격 12%. 같은 밑선. 라벨은 각 형상 아래 12px.
- **카운트다운 패널**은 무대에서 나온다. 왼쪽 단 CTA 아래에 한 줄짜리 얇은 패널(숫자 셋 + "아직 정해지지 않은 것" 칩 셋)로 내린다. 무대 위에 유리 카드가 있으면 형상이 또 가려진다.
- **폰(lg 아래)**: 카피 아래에 무대를 한 단으로(너비 100%, 높이 44vw), 두 형상 나란히(각 너비 42%). 카운트다운은 그 아래. 무대는 첫 화면 안에 들어오지 않아도 되지만(폰은 세로가 길다) 카피 바로 다음이어야 한다.
- 무대의 사각형을 JS로 재서(`getBoundingClientRect`) 월드 좌표로 바꾸는 방식은 지금 `placeShapes()` 그대로. 다만 **리사이즈와 폰트 로드 뒤에도 다시 잰다**(지금은 2초마다 폴링. `ResizeObserver`로 바꾼다).

### 1.2 형상은 정면, 가장자리가 두껍고, 속은 성기다

- 기울기 **0°**. 원근 왜곡 없이 화면 평면에 정렬(빌보드). 3° 포인터 패럴랙스는 평행 이동만.
- 점 예산: 데스크톱 티어 2,800 중 **형상 둘에 1,800**(각 900), 나머지 1,000은 깊이 층(1.3). 폰 900 중 형상에 600(각 300), 깊이 층 300.
- 형상 점의 **75%가 가장자리**(지금 78%지만 띠 폭이 6%라 두꺼운 테두리로 보임 → 띠 폭 **3%**로 좁혀 선처럼 읽히게), 25%가 속. 가장자리 점 크기 2.8px, 밝기 1.0, 색 `hi0`. 속 점 1.4px, 밝기 0.35, 색 `accent1`.
- 가장자리에 **흐르는 빛**: 구운 순서(`aRank`)를 위상으로 써서 윤곽을 따라 밝기의 파도가 12초에 한 바퀴 돈다(진폭 ±30%). 먼지가 아니라 살아 있는 선으로 읽힌다.
- 블룸은 형상 점에 걸리지 않게 임계값을 등불 위로. 형상은 선명해야 한다.
- 굽기 스크립트 `scripts/build-shape-points.py`의 띠 폭과 비율만 바꾸고 다시 굽는다. 서울 단순화 64 꼭짓점은 그대로.

### 1.3 등불과 강은 무대 안에서만

- 등불은 두 형상 사이, 밑선보다 조금 아래. 반사 띠는 **무대 폭 안에서만**, 높이는 무대의 10%. 화면 폭 전체의 수평선을 **없앤다**.
- 히어로가 화면에서 나가면(스크롤 진행 `#record` 시작 지점) 등불과 반사는 0.6화면에 걸쳐 사라진다. 그 뒤로는 어떤 스크롤 위치에서도 고정 수평선이 없다.
- `crossing` 국면의 목적지는 화면 y가 아니라 **깊이 층 안의 먼 점**(z 뒤쪽, 화면 중심 근처)이다. 건너간 점들은 거기서 성좌가 된다.

### 1.4 깊이 층을 되살린다 (8월의 것)

- 8월 `field`의 입자 필드를 **밀도 35%, 밝기 25%, 블룸 없음**으로 화면 전체에 깐다. 컬 노이즈 드리프트, 3° 패럴랙스, 얕은 카메라 돌리(스크롤에 따라 z 6 단위) 그대로. 형상은 그 앞에 선다.
- 이 층은 모든 스크롤 위치에서 있다. 본문 뒤에서는 카드 면이 가려 주고, 챕터 사이 여백과 270px 이음매에서 보인다. 그래서 페이지 어디서도 배경이 "빈 남색"이 아니다.
- 그룹 챕터(`#naru` 이후)에서는 드리프트 속도 50%, 밝기 15%로 더 잔잔하게.

### 1.5 국면을 눈에 보이는 자리에 맞춘다

```
banks     히어로가 화면에 있는 동안. 형상 정지(숨 진폭 지금의 30%), 등불 켬.
gather    히어로 하단이 뷰포트 상단을 지나는 순간부터 0.4화면. 형상이 속부터 풀리고 가장자리가 마지막에 떠난다. 등불·반사 페이드아웃.
crossing  #record 본문 동안. 점들이 깊이 층 안으로 들어가 화면 중심 뒤쪽의 먼 점을 향해 흐른다. 트레일 길어짐. 카드 뒤에서는 안 보여도 되고, 사진 벽과 언론 줄 사이 여백, #record→#december 사이 여백에서 보인다.
arrived   #december 중반부터. 먼 점 둘레의 성좌로 가라앉아 깊이 층과 섞인다. 이후 그룹 챕터는 잔잔한 깊이 층뿐.
```

국면 경계는 지금처럼 앵커 offsetTop에서 읽는다(상수 금지). 정지 토글은 `banks`로 얼어붙는다.

## 2. 하지 않는 것

- 8월 `field` 경로 변경(`/2026-08` 픽셀 diff 0).
- 히어로 카피, 카운트다운의 내용, 형상 원본(로고 섬, KOSTAT 64 꼭짓점) 변경.
- 형상 외곽선을 실선으로 긋기, 면 채우기, 주황 점 추가, 화이트아웃, 두 번째 등불.
- "남는 자리에 놓기", 감광 규칙, 히어로 아래 띠 같은 우회. 형상은 무대에 있다.

## 3. 검증 (전부 **움직임 켠 실제 브라우저**, `prefers-reduced-motion` 없이, 로드 후 6초)

1. `npx tsc --noEmit`, `npm run build`, 콘솔 오류 0.
2. **첫 화면 안에 있는가**: 1280×720, 1366×768, 1440×900, 1536×864, 1920×1080, 2000×1100에서 스크롤 0. JS로 무대 사각형과 라벨 둘의 `getBoundingClientRect`를 읽어 **전부 뷰포트 안**(bottom ≤ innerHeight)이고, 무대의 세로 중심이 뷰포트 높이의 40~60% 사이여야 한다. 여섯 값을 체인지로그 표로.
3. **알아보기**: 각 해상도 스크롤 0 스크린샷에서 라벨을 가리고 봐도 왼쪽이 로고 심볼과 같은 섬, 오른쪽이 서울 경계로 읽혀야 한다. `.shots/naru/bg-fix/compare-shapes.png`에 로고 심볼·KOSTAT 경계·실제 화면을 나란히.
4. **수평선 없음**: 스크롤 0 / 900 / 2000 / 3600 / 6000 / 8000 스크린샷에서 화면 폭 전체를 가로지르는 밝은 줄이 없어야 한다. 각 스크린샷의 행별 평균 휘도를 구해 이웃 행보다 3배 이상 밝은 행이 없는지 스크립트로 확인.
5. **건너는 장면**: 스크롤 900과 2000 사이를 200px 간격으로 찍어, 여백 영역에 입자가 이동하는 것이 연속 프레임에서 보여야 한다(같은 점의 위치가 프레임마다 화면 중심 쪽으로 움직임).
6. **깊이 층**: 스크롤 6000(그룹 챕터)에서 캔버스만 찍어 입자가 화면 전체에 분포하는지(4분면 각각에 있음).
7. 카피 뒤 휘도는 이전 체인지로그의 기준을 넘지 않을 것. fps 60(1440), 45+(폰).
8. `/2026-08` 전후 픽셀 diff 0.
9. 체인지로그 `docs/changelogs/changelog-september-XX-2026-bg-fix.md`. 커밋 셋으로 나눠서(`fix(bg): 형상을 히어로 오른쪽 무대로 옮긴다` → `fix(bg): 형상을 정면으로, 가장자리를 선으로` → `feat(bg): 깊이 층을 되살리고 수평선을 없앤다`). **`main` 푸시 전에 1~8.** 특히 2번은 여섯 해상도 전부에서 통과해야 한다. 한 해상도만 보고 맞춘 것이 이번 문제의 원인이다.
