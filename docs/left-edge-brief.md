# 레이아웃 브리프: 글은 한 줄의 왼쪽 끝에서, 가운데는 그림만

대상 레포: `website` (커밋 `aa6f826` 기준). 바꾸는 파일은 `components/home/NaruHome.tsx`, 필요하면 `components/ui/typography.ts`. 카피, 배경, 색, 글자 크기, 읽기 판의 모양, `/2026-08`은 건드리지 않습니다. 체인지로그는 `CLAUDE.md` 규칙대로.

## 0. 결론 한 줄

**글(제목, 알약 라벨, 문단, 목록, 카드, 버튼)은 전부 하나의 왼쪽 끝에서 시작합니다. 가운데 정렬은 "그림"(숫자 줄, 노선도)과 푸터에만 씁니다.**

## 1. 지금 무엇이 뒤섞였나 (배포본 실측, 1440×900과 390×844)

9월 25일 가독성 브리프가 "챕터 머리만 가운데, 나머지는 왼쪽"을 정했고, 9월 26일 한 축 브리프가 블록을 가운데 축에 모았습니다. 그 결과 **챕터마다 가운데에서 왼쪽으로 한 번씩 뒤집히고, 챕터 중간에도 가운데로 튀는 블록이 섞여 있습니다.**

| 자리 | 지금 | 문제 |
| --- | --- | --- |
| 챕터 머리 넷(알약 + h2 + 리드) | 가운데 | 리드 문단(`lg:text-center`, 649, 1065, 1368, 1493행) 바로 아래 문단은 왼쪽. 같은 글 흐름 안에서 한 줄 사이에 뒤집힘 |
| `#naru` 머리의 인장 로고, 1155행 문단 | 가운데 | 바로 아래 "8월이 남긴 것"은 알약까지 왼쪽 |
| 알약 라벨 | 챕터 것은 가운데, 챕터 안 것("제로백 빌더톤 2026.08", "변하지 않는 두 개")은 왼쪽 | 같은 모양이 두 자리에 |
| 히어로 | 데스크톱 왼쪽, 폰 가운데(524행 `text-center lg:text-left`) | 폰에서는 히어로 가운데 → 본문 왼쪽 |

| 버튼 | 히어로 폰은 가운데 쌓임, 본문은 왼쪽 | |

## 2. 규칙

```ts
// DECIDED 2026-09-29 (사용자: "어떤 건 다 left에 있다가 갑자기 다 센터로 가고, 뒤죽박죽.
// 문장들과 버튼들도"): 글은 하나의 왼쪽 끝에서 시작합니다. 제목, 알약 라벨, 리드, 문단,
// 목록, 카드, 버튼 모두. 가운데 정렬은 그림에만 씁니다: #december의 숫자 줄(5일, 2회,
// 2026-09-26 사용자 요청으로 가운데)과 5일 노선도. 그리고 푸터(맺음).
// 9월 25일의 "챕터 머리는 가운데" 규칙을 이 규칙이 대신합니다. 머리가 가운데이고 본문이
// 왼쪽이면 챕터마다 한 번씩 뒤집힙니다.
```

### 2.1 왼쪽 끝은 하나

- 글이 든 블록은 전부 `READ` 폭(`mx-auto max-w-3xl`) 안에 둡니다. 그래서 1440에서 글의 왼쪽 끝은 288 하나, 폰에서는 27 하나입니다.
- 지금 `WIDE`인 **글 블록**(AI 활용 범위 세 칸, 아쉬웠던 다섯 카드, General Mentoring 상자, 세 층 도식, 세 곳 카드)을 `READ`로 옮깁니다. 칸 수는 데스크톱에서 그대로 두되 `READ` 폭 안에서 나눕니다(세 칸이면 칸당 약 270px). 너무 좁아 글이 한두 자씩 끊기면 `md`에서 두 칸, 폰에서 한 칸으로 내립니다.
- `WIDE`는 그림(노선도)에만 남깁니다.

### 2.2 가운데를 쓰는 곳 (이 셋뿐)

1. `#december`의 숫자 줄(5일, 2회). 사용자가 9월 26일 가운데로 요청했습니다. 그대로 둡니다.
2. 5일 노선도와 그 범례("제출이 있는 날", "General Mentoring, Day 1부터 Day 3까지" 알약 포함).
3. 푸터(로고, 크레딧, 링크).

그림 안쪽의 라벨 정렬(노선도의 Day 이름, 세 층 도식 상자 안 글)은 그대로입니다.

### 2.3 왼쪽으로 옮기는 것

- **챕터 머리 넷**: 알약, h2, 리드 문단을 `READ`의 왼쪽 끝에 맞춥니다. `lg:text-center`를 전부 지웁니다(649, 1065, 1155, 1368, 1493행). h2의 크기, 줄 수, 색은 그대로입니다.
- **`#naru` 인장 로고**: 머리의 왼쪽 끝에 맞춥니다(1137행 `mx-auto` 제거). 크기는 그대로.
- **히어로(폰)**: 524행 `text-center`를 지워 폰에서도 왼쪽. 553, 556행 문단의 `mx-auto`, 561행 버튼 줄의 `justify-center`, 424행 사진 캡션의 `text-center`도 같이. 폰 버튼은 세로로 쌓되 왼쪽.
- **버튼**: 모든 버튼 줄은 글의 왼쪽 끝에서 시작합니다(`justify-start`).

### 2.4 건드리지 말 것

카피, 글자 크기, 색, 챕터 순서, 배경(WebGL)과 형상 전환 구간, 읽기 판의 CSS(판은 `READ`/`WIDE`를 따라가므로 판 폭이 바뀌면 덮개 구간이 다시 계산되는지만 확인), `/2026-08`, `/quiz`. em dash 금지, 가운뎃점 새로 쓰지 않음.

## 3. 검증

측정은 각 요소의 `getBoundingClientRect()`와 계산된 `text-align`, 줄 상자(`Range.getClientRects()`)의 가운데로 합니다. 1440×900, 1280×800, 1000×560, 390×844 네 크기.

| # | 항목 | 기준 |
| --- | --- | --- |
| 1 | 가운데 글 | `main` 안에서 줄 상자가 컨테이너 가운데에 놓인 글(가운데 정렬)이 2.2의 세 자리 밖에 **0곳** (버튼 안 글자 제외) |
| 2 | 왼쪽 끝 | 2.2 밖의 모든 글 블록(h2, h3, h4, p, li, dd, 알약, 버튼, 카드)의 바깥 상자 왼쪽 끝이 `READ` 왼쪽 끝과 같음(±2px). 카드 안쪽 글은 카드 안쪽 여백만큼 들어간 것을 허용 |
| 3 | 뒤집힘 | 문서를 위에서 아래로 읽을 때, 이웃한 두 글 블록 사이에 정렬이 바뀌는 곳이 2.2의 그림 앞뒤 말고 **0곳** |
| 4 | 좁은 칸 | `READ`로 옮긴 여러 칸 블록에서 한 줄에 네 자 이하로 끊기는 줄 0개 |
| 5 | 읽기 판과 형상 | 판 폭이 바뀐 뒤에도 "형상은 판 뒤에서만 바뀐다"(9월 26일) 검증 1이 네 크기에서 위반 0곳 |
| 6 | 아카이브 | `/2026-08`, `/quiz` 픽셀 차이 없음 |

1440×900과 390×844에서 적용 전후 전체 페이지 스크린숏에 `READ` 왼쪽 끝 세로선을 그어 나란히 보여 주세요.
