## 1. 프로그램 `#december` (4,197 → ≤ 2,600)

폰에서만 아래를 적용한다. 데스크톱은 그대로.

1. **워크샵 상자 셋을 Day 카드 안으로.** 지금은 카드 4장 뒤에 워크샵 카드 3장이 따로 선다(약 350px). 폰에서는 해당 Day 카드 맨 아래에 "워크샵 · Problem Discovery" 한 줄(라벨 + 이름, 설명은 생략)로 넣고 별도 상자는 `lg:` 이상에서만 렌더한다.
2. **참여 플로우 스트립을 폰에서 숨긴다.** 등록 → 팀 본딩 → 닷새 → 결과 공유회. 세로 상자 4개에 화살표 3개(약 350px)인데 정보가 없다. `hidden lg:block`.
3. **아쉬웠던 넷을 폰에서 1열로.** 2열이라 150px 폭 안에서 "12월" 답이 한 줄에 서너 글자씩 끊긴다. 1열에 카드 높이는 줄어들고(가로로 펴지므로) 합계는 비슷하거나 짧다. 번호 배지는 제목 왼쪽에 인라인.
4. **노선도와 Day 카드의 중복.** 둘 다 둔다(노선도는 한눈, 카드는 내용). 대신 Day 카드의 "→ 그날의 한 줄"은 유지하고 본문 문장은 폰에서 `line-clamp-2`.
5. **"5일 / 2회" 숫자 쌍**은 유지(작다).
6. **"새로 정해지는 것은 이 자리에 업데이트합니다"와 "기획 초안입니다"** 두 안내 줄이 따로 있으면 한 줄로 합친다(폰에서만).
7. CTA 블록(등록 안내 + 출제사 문의 링크)은 그대로.

## 2. 카운트다운 (히어로)

- 지금 KST와 SGT **두 줄**, 초 단위. 닷새짜리 이벤트에 과하다. **한 줄로**: `82일` + "크로싱 서울까지 · 서울 기준". 시·분·초는 폰에서 숨기고 데스크톱에서도 일·시·분까지만(초 삭제). SGT 줄은 삭제(시차 한 시간, 날짜가 같다).
- **폰에서 위치를 사진 위로.** 지금은 CTA → 사진 4장 → 카운트다운 → 프로그램 순이라 카운트다운이 사진과 다음 챕터 사이에 끼어 있다. CTA 바로 아래 한 줄, 그다음 사진. 데스크톱(왼쪽 단 CTA 아래)과 같은 순서가 된다.

## 3. 8월이 남긴 것 `#record`

- **사람이 빠져 있다.** 홈 흐름 브리프 1.3의 `RecordTabs`(멘토 / 연사와 피드백 패널, 링크드인, 패널 사진)를 숫자 아래에 넣는다. 아직 안 넣은 이유가 있으면 체인지로그에 적고, 없으면 넣는다. 폰에서 탭 레일은 가로 스크롤, 패널은 1열.
- 숫자 5칸이 2열이라 "9팀"이 왼쪽에 혼자 남는다. 폰에서 **3 + 2**(첫 줄 셋, 둘째 줄 둘 가운데) 또는 다섯째 칸 전폭. 데스크톱 한 줄 다섯은 그대로.
- 언론 줄의 CNA 영문 제목이 폰에서 4줄. `line-clamp-2` + 전체 제목은 `title` 속성으로. 링크는 그대로.

## 6. 배경 WebGL (폰)

DOM을 숨기고 캔버스만 390×844에서 스크롤 0 / 850 / 1,700 / 3,400 / 5,100 / 6,800 / 7,700 / 10,200 / 12,000 아홉 지점을 찍었다(`.shots/naru/mobile-fix/canvas-before/`에 같은 방법으로 남길 것). 실측:

| 지점 | 보이는 것 | 문제 |
| --- | --- | --- |
| 0, 850 | 등불이 **왼쪽 가장자리(x≈5%)**에 반쯤 잘려 있고, 그 아래 반사 기둥. **화면 폭 전체의 수평선**(강 반사 띠) | 세로 화면에서 등불 자리가 데스크톱 좌표(왼쪽 셋째 자리)를 그대로 써서 가장자리에 붙음. 수평선은 폰에서도 본문을 가름 |
| 0 | 나루 심볼이 **없다** | 폰에서 심볼이 히어로에 서지 않는다. 심볼 브리프의 "히어로 뒤 워터마크, 폰 110vw"가 세로 화면에 적용되지 않음 |
| 1,700 이후 전부 | 심볼 윤곽이 화면 가운데 같은 자리에 **계속 고정** | 국면(banks → gather → crossing → arrived)이 세로 화면에서 돌지 않는다. 프로그램·얻는 것·8월·나루·학생회 챕터 뒤에 같은 그림이 붙박이로 있다 |
| 3,400 이후 | 주황 점이 심볼과 따로 **왼쪽·왼쪽 위를 떠돈다** | 등불이 심볼의 나루 점 좌표에 묶여 있지 않고 독립 좌표로 그려짐 |
| 5,100, 6,800, 10,200, 12,000 | 등불 둘레에 **지름 60~90vw의 반투명 고리**(테두리가 있는 원) | 폰(블룸 없음) 경로의 등불 스프라이트가 방사 그라데이션이 아니라 가장자리가 있는 원. 확대되어 본문 뒤에 렌즈 고리처럼 보임. 사용자가 "해가 사이드에 있어서 이상하다"고 본 얼룩의 정체가 이것과 위의 등불 위치다 |

캡처는 소프트웨어 GL(SwiftShader)이라 실기기와 밝기가 다를 수 있다. 위치와 고리 모양은 실기기에서도 같다. 아래를 고친 뒤 실기기(iPhone Safari) 스크린샷도 한 장 남긴다.

고칠 것(세로 화면, `matchMedia("(orientation: portrait)")` 또는 `innerWidth < 1024`):

1. **심볼을 히어로에 세운다.** 뷰포트 가운데(x 50%, y 56%), 너비 110vw, 정면. 스크롤 0에서 보여야 한다. 카피가 그 위에 얹히므로 밝기는 데스크톱 워터마크 값(가장자리 0.45)의 80%.
2. **등불은 나루 점에 묶는다.** 모든 국면에서 등불의 화면 좌표 = 심볼 변환을 거친 `NARU_POINT`. 독립 좌표·독립 드리프트를 없앤다. 심볼이 가운데에 있으니 점은 화면 x 약 55%, 남쪽 해안에 온다. 안전장치로 등불 x를 뷰포트의 15~85% 안에 클램프.
3. **세로 화면에서는 강 반사(수평선·기둥)를 그리지 않는다.** `WaterSurface`를 portrait에서 마운트하지 않는다. 등불의 빛만 남는다.
4. **등불 스프라이트를 가장자리 없는 방사 감쇠로.** 블룸 없는 경로용 텍스처를 가우시안 감쇠(중심 1 → 반지름 끝 0, 링 없음)로 다시 굽고, 화면 크기 상한 28vw, 최대 불투명도 0.35. 데스크톱(블룸 있음)도 같은 텍스처를 쓰되 블룸이 나머지를 한다.
5. **국면을 세로 화면에서도 돌린다.** 히어로 안 정지 → 히어로가 나가면 0.4화면에 걸쳐 풀림 → 프로그램·얻는 것·8월 뒤에서는 **심볼 없음**(깊이 층만, 밝기 0.2) → `#naru`부터 심볼이 90vw로 희미하게(데스크톱 값의 50%) 다시 선다. 앵커 offsetTop 계산이 portrait에서 건너뛰어지는 분기가 있으면 없앤다.
6. 깊이 층 밝기 폰 0.4 → 0.2, 입자 크기 하한 1px 낮춤. 폰은 블룸 없음 그대로.
7. `motionScale` 0(정지 토글, `prefers-reduced-motion`)에서 폰 정지 화면 = 히어로의 심볼 + 나루 점. 고리·수평선 없음.

## 7. 헤더 (폰)

- 로고 줄(52px) + 앵커 칩 레일(48px) = 100px 고정, 화면의 12%. 8월 페이지의 모바일 크롬 auto-hide(`lib/useScrollDirection.ts`, 2026-08-02 체인지로그)가 홈 헤더에도 걸려 있는지 확인한다. 안 걸려 있으면 건다: 아래로 스크롤하면 칩 레일이 접히고 위로 스크롤하면 펴진다. 로고 줄은 항상.
- 칩 레일에서 "8월"이 잘린다. 칩 라벨 다섯이 390px에 들어가지 않으니 가로 스크롤은 유지하되, 현위치 칩이 항상 보이게 `scrollIntoView({ inline: "center" })`.

## 8. 소소한 것

- `src`가 없는 `<img>` 하나(폭 180px, lazy). 원인을 찾아 없앤다(언론 줄의 제호 로고 자리로 추정).
- 히어로 사진 넷의 `sizes`. 390px에서 요청 폭이 작아 dpr 3 실기기에서 흐릴 수 있다. `sizes="(max-width: 1024px) 45vw, 22vw"`로 맞추고 실제 요청 URL의 `w=` 값을 확인.
- "등록은 아직 열리지 않았습니다"가 프로그램 CTA와 참가자 카드에 두 번. 참가자 카드 쪽을 "등록이 열리면 이 자리에서"로 줄이거나 둘 중 하나만.
- `#naru`(2,384px)와 `#join`(2,046px)은 이번에 손대지 않는다. 사용자가 판형을 정한 자리다.
