### 1.2 무엇이 어긋났나

**첫째, 서울 이벤트 챕터에 서울이 없습니다.** `#december`는 크로싱 서울의 프로그램, Day 0~4, 세션, 8월에 아쉬웠던 것입니다. 3,308px 내내 배경은 해가 내려가는 장면입니다. 좋은 장면이지만 이 챕터의 것이 아닙니다.

**둘째, 서울이 서 있을 자리가 없습니다.** 한 시계 브리프에서 서울의 등장을 `#gains`로 옮겼는데 건너기의 시작(`#naru` − 0.5vh)은 그대로였습니다. 그래서 서울은 떠오르는 중에 이미 건너기 시작합니다.

**셋째, 싱가포르가 마지막 챕터까지 서 있습니다.** `#join`은 "왜 이 자리가 필요한가"이고 그 안이 **싱가포르에서 / 한국에서 / 그 밖의 나라에서** 셋입니다. 세 곳을 나란히 두는 챕터 뒤에 싱가포르 하나만 서 있으면 셋 중 하나를 편드는 그림이 됩니다.

## 2. 챕터에 맞춘 지도

앵커로 적습니다. 카피가 늘어도 챕터를 따라갑니다. "온전"은 떠오름과 사라짐을 뺀, 형상이 다 선 길이입니다.

| 구간 | 앵커 | 배경 | 데스크톱 | 폰 |
| --- | --- | --- | --- | --- |
| 0 나루터 | 0 → `#top` 하단 | 수면, 해 | 1,037 | 1,218 |
| 1 건넘 | `#top` 하단 → **+1.2vh** | 해가 내려가 나루 점이 됨 | 1,080 | 1,013 |
| 2 서울 | 구간 1 끝 → `#naru` − 0.5vh | 서울 윤곽 (앞 0.6vh는 떠오름) | 2,678 (온전 **2,138**) | 4,243 (온전 **3,737**) |
| 3 크로싱 | `#naru` − 0.5vh → +1.5vh | 서울 → 싱가포르 | 1,350 | 1,266 |
| 4 싱가포르 | 구간 3 끝 → `#join` − 0.6vh | 싱가포르 윤곽 | 온전 **1,895** | 온전 **2,067** |
| 5 세 곳 | `#join` − 0.6vh → +0.8vh, 그 뒤 끝까지 | **형상이 흩어지고 나루 점만 남음** | 720 + 나머지 | 675 + 나머지 |

온전 길이로 서울 ÷ 싱가포르가 데스크톱 **1.13**, 폰 **1.81**입니다. 지금은 둘 다 0입니다.

### 2.1 왜 이렇게 나누나

- **구간 1을 1.2화면으로.** 해가 내려가 점이 되는 데 3.7화면(폰 5.5화면)은 필요 없습니다. 히어로에서 이미 한 화면을 해와 보냈고, 1.2화면이면 내려가는 것이 다 보입니다. 1.5까지는 괜찮고 그 위로는 서울을 깎습니다.
- **구간 1이 `#december`의 머리에 걸리는 것은 의도입니다.** `#december`의 h2(y 1,237)는 챕터 상단에서 200px 아래라, 그 제목을 읽을 때 해는 아직 내려가는 중입니다. 해가 점이 되는 것이 "서울로 건너옴"의 문턱이고, 그 문턱을 넘으면 서울이 섭니다. 그래서 검증 3은 h2가 아니라 챕터의 본문(Day 0~4)에서 봅니다.
- **구간 2가 `#december`의 본문과 `#gains` 전체.** 크로싱 서울의 프로그램과 얻는 것을 읽는 동안 서울이 서 있습니다.
- **구간 3은 그대로.** `#naru`의 제목 "건너는 건 각자가 한다"(y 5,746)가 건너기의 70% 지점에 옵니다. 제목이 건넘을 말할 때 형상이 건너고 있습니다.
- **구간 4가 `#naru` 챕터.** 그 안에 `#record`(8월이 남긴 것, 싱가포르에서)가 있고, 싱가포르는 그 직전에 도착합니다.
- **구간 5를 `#join` 상단보다 0.6화면 앞에서 시작합니다.** 첫 판은 `#join` 상단에서 시작했는데, 그러면 `#join`의 제목을 읽을 때(데스크톱 y 8,779, 폰 10,467) 형상이 아직 87~91% 서 있습니다. 읽는 사람은 제목이 화면 위쪽 5분의 1에 올 때 그 제목을 읽습니다. 그때 형상이 거의 비어 있어야 합니다. 그래서 `#join` − 0.6vh에서 시작해 0.8vh 동안 거둡니다.

## 3. 실행

### 3.1 `config.ts`

`SEOUL_WATERMARK`에 구간 경계를 모읍니다. 흩어져 있던 `revealVh`, `morph`를 여기로 옮기고 새 값을 더합니다.

```ts
  // ── 구간 지도 (DECIDED 2026-09-23, 챕터 지도 브리프) ─────────────────────
  // 앵커는 BackgroundScene.readAnchors가 읽습니다: #top 하단, #naru, #join.
  // 카피가 늘어도 챕터를 따라갑니다. 각 구간이 어느 챕터 위에 놓이는지는
  // 브리프 2장의 표에 있고, 그 표가 이 값들의 이유입니다.
  stages: {
    // 구간 1: 해가 내려가 점이 됩니다. #top 하단부터 이만큼(뷰포트 높이 배).
    // 전에는 #gains 상단까지였고, 그러면 #december 전체가 해가 지는 장면이었습니다.
    // 뷰포트 배수라 데스크톱과 폰이 같은 길이로 봅니다(전에는 3.7화면 대 5.5화면).
    descendVh: 1.2,
    // 구간 2: 서울. 구간 1 끝에서 이만큼에 걸쳐 떠오른 뒤, 건너기 시작까지 섭니다.
    revealVh: 0.6,
    // 구간 3: 서울 → 싱가포르. #naru 위쪽 startVh 앞에서 시작해 spanVh 동안.
    morph: { startVh: 0.5, spanVh: 1.5 },
    // 구간 4: 싱가포르의 밝기. 건너기가 끝난 뒤 1vh에 걸쳐 이 값으로 내려갑니다.
    // #naru와 #record 본문이 그 위에 놓이므로 온전한 1.0이 아니라 0.8.
    // 5장 검증 7(본문 대비)을 통과하지 못하면 이전 값 0.6으로 되돌립니다.
    singaporeBright: 0.8,
    // 구간 5: 형상을 거둡니다. #join 상단 startVh 앞에서 시작해 spanVh 동안 0으로.
    // 세 곳(싱가포르, 한국, 그 밖)을 말하는 챕터 뒤에 싱가포르 하나만 서 있으면
    // 셋 중 하나를 편드는 그림이 됩니다. 나루 점만 남깁니다.
    // #join의 제목을 읽을 때 형상이 비어 있도록 챕터보다 조금 앞에서 시작합니다.
    dissolve: { startVh: 0.6, spanVh: 0.8 },
  },
```

`calmBright`는 `singaporeBright`로 바뀝니다(이름과 값). 세로 화면의 `portrait.naruBright`, `portrait.naruW`, `portrait.naruCy`는 지웁니다(3.2의 세로 분기가 더는 쓰지 않음). `portrait.heroW`, `heroCy`, `heroBright`, `singaporeW`는 남깁니다.

### 3.2 `BackgroundScene.ts`

`readAnchors`에 `#join` 상단(`this.joinTop`)을 더합니다. `#join`이 없는 페이지에서는 `Infinity`로 둬서 구간 5가 오지 않게 합니다.

water 분기의 구간 계산을 이렇게 바꿉니다.

```ts
      const S = W.stages;
      const descendEnd = this.heroEnd + S.descendVh * vh;
      const morphStart = this.naruTop - S.morph.startVh * vh;
      const morphEnd = morphStart + S.morph.spanVh * vh;

      // 구간 1. 선형으로 넘깁니다. water 셰이더가 uStage1에 자기 곡선(pow 12 등)을
      // 이미 씌우므로, 여기서 ss()를 한 번 더 씌우면 해가 내려가는 모양이 바뀝니다.
      const s1 = clamp((this.scrollY - this.heroEnd) / (S.descendVh * vh), 0, 1);
      // 구간 2 진행. 셰이더가 uStage2로 나루 점을 화면 가운데로 올립니다(my).
      // 구간 1 끝부터 건너기 시작까지로 다시 정의합니다.
      const s2 = clamp((this.scrollY - descendEnd) / Math.max(morphStart - descendEnd, 1), 0, 1);
      const morph = ss(clamp((this.scrollY - morphStart) / (S.morph.spanVh * vh), 0, 1));
      this.particles?.setMorph(morph);
      this.water.setStages(s1, s2, morph);

      // 떠오름 길이는 구간 2보다 길 수 없습니다(챕터가 짧아져도 떠오르다 건너지 않게).
      const revealSpan = Math.max(Math.min(S.revealVh * vh, morphStart - descendEnd), 1);
      const reveal = ss(clamp((this.scrollY - descendEnd) / revealSpan, 0, 1));
      const settle = ss(clamp((this.scrollY - morphEnd) / vh, 0, 1));
      const dissolveStart = this.joinTop - S.dissolve.startVh * vh;
      const dissolve = ss(clamp((this.scrollY - dissolveStart) / (S.dissolve.spanVh * vh), 0, 1));
      const shapeOpacity = reveal * (1 - dissolve);
```

불투명도와 배치는 두 분기 모두 이렇게 합니다.

```ts
      const portrait = vh > window.innerWidth;
      if (portrait) {
        // 세로 화면은 크기와 자리가 처음부터 끝까지 같습니다. calm으로 옮기지 않습니다.
        opacity = shapeOpacity * W.portrait.heroBright * (1 - settle * (1 - S.singaporeBright));
        this.placeSeoul(W.portrait.heroW, W.portrait.heroCy);
      } else {
        opacity = shapeOpacity * (1 - settle * (1 - S.singaporeBright));
      }
      this.particles?.updateCrossing(this.fieldTime, this.scroll, this.motionScale,
        { gather: 0, crossing: 0, arrived: 0, calm: settle }, 0);
```

`setShapeLook`의 인자(가장자리 밝기, 안쪽 밝기, 점 크기 보간)는 지금 그대로 두고 `opacity`만 위 값으로 넘깁니다.

**구간 2가 모자라면 경고합니다.** `morphStart − descendEnd < S.revealVh * vh + vh`이면(서울이 온전히 설 자리가 한 화면이 안 되면) 개발 빌드에서 `console.warn`을 찍으세요. 앵커를 읽을 때 한 번만. 지금 배포된 상태가 정확히 그런 경우였고, 아무도 몰랐습니다.

### 3.3 나루 점은 그대로

구간 5에서 형상이 사라져도 나루 점(water 셰이더의 깊은 물 층)은 남습니다. 지금 코드가 이미 그렇게 되어 있습니다. 점이 화면 가운데로 올라오는 `my`의 이동도 그대로이고, 3.2에서 `uStage2`만 새 구간 2에 맞춰 다시 정의했습니다.

### 3.4 구간 5의 모양 (선택)

`shapeOpacity`를 0으로 내리는 것만으로 형상은 사라집니다. **흩어지는 느낌**을 더하려면 버텍스 셰이더의 `uBreath`를 `dissolve`에 따라 0.3 → 1.6으로 올리세요. 새 경로를 만들지 말고 있는 유니폼만 씁니다. 먼저 불투명도만으로 배포해서 보고 정해도 됩니다.

### 5.1 측정 방법

- 캔버스만 보려면 DOM을 지우지 말고 `header,main,footer`의 `opacity`를 0으로(지우면 캔버스가 폴백으로 바뀝니다).
- 스크롤은 `window.scrollTo`로 옮겨도 배경 구간은 맞게 갑니다(배경은 `scrollY`를 읽음). framer 효과를 같이 볼 때만 `mouse.wheel`을 씁니다.
- 형상은 파도 때문에 시간에 따라 조금 변하므로 각 지점에서 **3프레임 이상** 찍고 중앙값을 봅니다.
- 형상 잉크: `lum − GaussianBlur(lum, 4) > 9`인 픽셀 중 주황이 아닌 것. 주황: `r > g+18 && r > b+10 && lum > 28`.
- "제목을 읽을 때"는 **`scrollY = h2의 문서 y − 0.2vh`** (제목이 화면 위쪽 5분의 1)로 정의합니다.
- 기준 수치의 구간 길이는 **숫자로 계산해 확인**하고(앵커와 config 값만으로 결정됨), 화면 기준은 스크린숏으로 확인합니다.

### 5.2 해 → 점 전환의 빛 구멍

지금 배포본에서 `uStage1`이 0.85~1.0인 동안 해의 빛은 꺼졌는데 점이 아직 밝지 않아 **가장 밝은 주황 픽셀이 104~111로** 떨어집니다(앞뒤는 156~171). 구간 1을 1.2화면으로 줄이면 이 구멍도 짧아지지만 사라지지는 않습니다.

1. 먼저 3.2까지만 적용하고 `s1` 0.70, 0.80, 0.85, 0.90, 0.95, 1.00, 그리고 `descendEnd + 0.1vh` 일곱 지점에서 주황 최고 휘도를 잽니다.
2. 모두 **120 이상**이면 끝. 셰이더를 건드리지 않습니다.
3. 120 아래가 있으면 `water.ts`에서 `dotAlive`(지금 `= uStage1`)가 해의 소멸보다 늦게 따라오는 것이 원인인지 봅니다. 그렇다면 점만 조금 일찍 밝히세요. 예: `dotAlive = smoothstep(0.0, 0.8, uStage1)`. `sunAlive`, `sink`, `H`, `lightY`는 건드리지 않습니다. 해가 내려가는 모양은 그대로 두고, 끝자락에 빛이 비는 한 박자만 메웁니다.
4. 원인이 다른 곳이면 고치지 말고 측정값과 추정 원인을 커밋 메시지에 남긴 뒤 사용자에게 보고합니다.

## 6. 사용자가 정할 것

1. **구간 1의 길이.** 1.2화면으로 적었습니다. 해가 지는 것을 더 오래 보고 싶으면 1.5까지. 그 위로는 서울이 깎입니다(1.5면 서울 온전이 데스크톱 1,868px).

4. **구간 5의 흩어짐(3.4).** 불투명도만으로 먼저 보고 정하세요.
