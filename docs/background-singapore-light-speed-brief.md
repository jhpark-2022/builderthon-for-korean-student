# 배경 브리프: 싱가포르의 빛을 좁게, 그리고 상한을 두고 움직입니다

대상 레포: `website` (커밋 `f53d556` 기준, 배포본 = `d52cf3e`의 배경). 바꾸는 파일은 `lib/background/config.ts`, `lib/background/scene/BackgroundScene.ts`, `lib/background/shaders/water.ts`(상수 두 개를 유니폼 하나로)입니다. 파문(ring)은 건드리지 않습니다.

## 0. 결론 한 줄

빛(나루 점)이 싱가포르 구간에서 움직이는 **폭을 절반으로 줄이고, 속도에 상한**을 둡니다. 파문의 모양, 밝기, 퍼지는 거리, 위상 속도는 그대로입니다.

## 1. 지금 무엇이 빠른가

배포본(`d52cf3e`)의 싱가포르 구간(건너기 끝 → 문서 끝):

- 점의 x는 `lx + sweep × sin(2π × smoothstep(uStage4))`. `sweep`는 가로 0.22, 세로 0.28(화면 폭 대비). 한 구간에 동쪽 끝 → 서쪽 끝 → 가운데로 한 바퀴 돌아, 이동 거리가 **화면 폭의 0.88배(폰 1.12배)**입니다.
- `uStage4`는 스크롤이 정한 값을 `s4Eased`가 초당 35%씩 따라갑니다. 지수 감쇠라 **한 번에 많이 스크롤할수록 처음 속도가 비례해서 커집니다.**

계산한 점의 최고 속도(휠이나 플릭 직후):

| 화면 | 스크롤 한 번 | 점의 최고 속도 |
| --- | --- | --- |
| 데스크톱 1440 | 휠 500px | 약 150px/s |
| 데스크톱 1440 | 한 화면 900px | 약 270px/s |
| 데스크톱 1440 | 바닥까지 플릭 | 약 1,000px/s (1초에 화면 폭의 70%) |
| 폰 390 | 플릭 1,500px | 약 155px/s (1초에 화면 폭의 40%) |

두 원인이 곱해져 있습니다. **폭이 넓고**(sweep), **큰 스크롤에 상한이 없습니다**(지수 감쇠). 파문은 점을 중심으로 그려지므로 점이 빨리 가면 파문 무늬 전체가 같이 밀려, 파문까지 빨라 보입니다. 파문 자체의 속도(`uRingPhase`, 0.5 + uFlow × 1.6 rad/s)는 바뀐 적이 없습니다.

## 2. 고치는 방법

둘 다 합니다. 하나만 하면 반쪽입니다.

### 2.1 폭을 절반으로 (`config.ts` → 유니폼)

`water.ts`의 상수 `mix(0.22, 0.28, portrait)`를 유니폼 `uSweep`으로 빼고 `config.ts`에서 정합니다.

```ts
// DECIDED 2026-09-23 (사용자: "빛 속도가 너무 빨라서 천천히. 커버하는 면적 때문이면 면적을 줄이면 됨").
// 싱가포르 구간에서 점이 가로로 도는 폭(화면 폭 대비, 한쪽). 0.22/0.28 → 0.12/0.15.
// 이동 거리가 화면 폭의 0.48배(폰 0.60배)로 줄고 같은 스크롤에 속도도 절반이 됩니다.
// 싱가포르 반폭(가로 0.33, 세로 0.40) 안쪽이라 점은 여전히 섬 위에 있습니다.
export const LIGHT_SWEEP = { landscape: 0.12, portrait: 0.15 } as const;
```

`BackgroundScene`이 `portrait` 여부를 이미 아니 값을 골라 `setSweep()`으로 넘깁니다(`WaterSurface`에 세터 하나).

### 2.2 속도 상한 (`BackgroundScene.ts`)

`s4Eased`의 한 프레임 이동량에 상한을 둡니다. 작은 스크롤은 지금처럼 부드럽게 따라가고, 큰 스크롤은 상한 속도로 흘러갑니다.

```ts
// DECIDED 2026-09-23: 지수 감쇠(초당 35%)만으로는 바닥까지 플릭했을 때 점이 1초에 화면 폭의
// 70%를 갔습니다. 진행도의 변화율에 상한을 둡니다. 0.05/s면 한 바퀴(진행도 0→1)에 20초 이상.
// 점의 최고 속도가 데스크톱 약 80px/s, 폰 약 28px/s를 넘지 않습니다.
const LIGHT_MAX_RATE = 0.05; // config.ts에 LIGHT_SWEEP 옆에 둡니다
const want = (s4 - this.s4Eased) * Math.min(1, dt * 0.35);
const cap = LIGHT_MAX_RATE * dt;
this.s4Eased = this.reduced ? s4 : this.s4Eased + Math.max(-cap, Math.min(cap, want));
```

모션 민감 설정(`this.reduced`)에서는 지금처럼 바로 그 자리에 섭니다.

## 3. 건드리지 말 것

- **파문 전부.** `ringGain`(0.28 + 0.72 × …, `arrived` 0.55 포함), `reach`(2.4 → 1.4), `phase = rr × 9.0 × K − uRingPhase`, `RING` 상수, `smoothstep(0.86, 1.0, sin(phase))`. 사용자가 지금 모양이 좋다고 했습니다.
- 점의 밝기와 크기(`exp(-rr / 0.009) × 0.42 …`).
- 점의 세로 이동(`my`), 구간 1~3, 형상, 챕터 지도.
- `sin(2π × …)`의 한 바퀴 경로. 폭만 줄입니다.
- em dash 금지. 결정은 `DECIDED 2026-09-23` 한국어 주석으로.

## 4. 검증

캔버스만 보려면 `header,main,footer`의 `opacity`를 0으로(DOM은 지우지 않음). 점의 위치는 주황 픽셀의 무게중심 x로 잽니다.

| # | 항목 | 기준 |
| --- | --- | --- |
| 1 | 큰 스크롤 | 싱가포르 도착 직후에서 바닥까지 한 번에 스크롤한 뒤 0.25초 간격으로 4초 캡처. 점의 최고 속도가 데스크톱 **90px/s 이하**, 폰 **35px/s 이하** (지금 약 1,000 / 155) |
| 2 | 작은 스크롤 | 휠 300px 뒤 점이 계단 없이 미끄러짐(연속 프레임의 x 변화가 단조) |
| 3 | 폭 | 구간 4 전체를 지나며 점의 x 범위가 가로 화면 폭의 **0.24 ± 0.03**, 세로 **0.30 ± 0.03** |
| 4 | 파문 불변 | 같은 스크롤 위치, 같은 `uRingPhase`에서 적용 전후 캡처를 점 중심을 맞춰 겹쳤을 때 파문 영역(점 반지름 0.02 밖)의 픽셀 차이 평균 **2/255 이하** |
| 5 | 모션 민감 | `prefers-reduced-motion: reduce`(페이지 안에서 켜지 않은 상태)에서 점이 스크롤 자리에 바로 섬 |
| 6 | 두 화면 | 1~4를 1440×900과 390×844에서 각각 |
| 7 | 아카이브 | `/2026-08` 배경 픽셀 차이 없음 |

## 5. 사용자가 정할 것

폭 0.12/0.15와 상한 0.05/s로 적었습니다. 더 느리게 원하면 상한을 0.03까지(한 바퀴 33초), 더 좁게 원하면 폭 0.08/0.10까지. 둘 다 `config.ts` 값 하나입니다.
