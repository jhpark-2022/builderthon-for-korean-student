# 배경 브리프: 서울은 짧은 것이 아니라 흐린 것입니다

대상 레포: `website` (커밋 `31a730a` 기준). 바꾸는 파일은 `lib/background/` 안뿐입니다. DOM, 카피, 라우트, 수파베이스, `/2026-08`은 건드리지 않습니다.

계측 대상: https://naru-crossing-seoul.vercel.app/ (1440×900 문서 10,499px, 390×844 문서 12,871px). 25지점 스윕과 한 지점 고정 10프레임 관찰.

## 0. 결론 한 줄

서울이 화면에 서 있는 스크롤 거리는 싱가포르와 거의 같습니다(1 : 1.14). **문제는 시간이 아니라 밝기입니다.** 서울은 자기 구간 내내 보일까 말까 한 밝기로 그려지고, 윤곽을 도는 ±30% 밝기 파도가 그 점들을 보였다 안 보였다 하게 만듭니다.

## 1. 시간은 거의 같습니다

앵커를 실측해 구간을 계산했습니다.

| | 데스크톱 | 폰 |
| --- | --- | --- |
| 서울 떠오름 | y 1,037 ~ 1,757 | y 1,218 ~ 1,893 |
| **서울 온전** | y 1,757 ~ 4,795 = **3,038px (31.6%)** | y 1,893 ~ 6,474 = **4,581px (38.1%)** |
| 건너는 중 | y 4,795 ~ 6,145 = 1,350px | y 6,474 ~ 7,740 = 1,266px |
| **싱가포르 온전** | y 6,145 ~ 9,599 = **3,454px (36.0%)** | y 7,740 ~ 12,027 = **4,287px (35.6%)** |
| 서울 : 싱가포르 | 1 : 1.14 | 1 : 0.94 |

폰에서는 서울이 오히려 더 깁니다. 그런데도 짧게 느껴집니다. 그러면 원인은 다른 데 있습니다.

## 2. 실제로 보이는 것

### 2.1 서울 구간 네 지점

데스크톱에서 서울이 온전해야 하는 구간의 네 지점을 캔버스만 찍었습니다.

| y | 스크롤 | 화면에 있는 것 |
| --- | --- | --- |
| 2,000 | 21% | 물, 해, 반사 기둥, 큰 고리. **서울 없음** |
| 2,800 | 29% | 물, 해, 반사 기둥, 밝은 고리. **서울 없음** |
| 3,600 | 37% | 물, 해, 큰 고리. **서울 없음** |
| 4,400 | 46% | 옅은 서울 윤곽이 처음 보임 |

DOM을 완전히 지운 캡처와 6%만 남긴 캡처가 같은 결과였습니다.

즉 사람이 서울을 서울로 알아보는 구간은 **y 4,400 언저리부터 건너기가 시작되는 4,795까지, 400px 남짓**입니다. 싱가포르는 3,454px 내내 또렷합니다. **체감 비율은 1 : 8입니다.**

### 2.2 원인 하나: 점이 깜빡입니다

스크롤을 y 2,800에 **고정해 놓고** 0.8초 간격으로 열 프레임을 찍었습니다.

| 시각 | 서울 점 픽셀 | 오른쪽 날개 |
| --- | --- | --- |
| 0.0s | 0 | 0 |
| 0.8s | 0 | 0 |
| 1.6s | 138 | 0 |
| **2.4s** | **845** | **650** |
| **3.2s** | **716** | **582** |
| 4.0s | 57 | 0 |
| 4.8s | 0 | 0 |
| 5.6s | 30 | 0 |
| 6.4s | 136 | 0 |
| 7.2s | 122 | 0 |

**스크롤을 한 픽셀도 움직이지 않았는데 서울이 나타났다 사라집니다.** 열 프레임 중 두 프레임에서만 읽힙니다.

범인은 `config.ts`의 이 값입니다.

```ts
wavePeriod: 12,     // 초
waveAmp: 0.3,
```

버텍스 셰이더가 윤곽을 따라 도는 밝기 파도를 겁니다.

```glsl
float wave = 1.0 + uWave.y * sin(6.2831853 * (aPhase - uTime / uWave.x));
vBright = mix(uInnerBright, uEdgeBright * wave, aEdge);
```

12초에 한 바퀴 도는 ±30% 파도입니다. 밝기에 여유가 있으면 "살아 있는 선"이 되지만, **기준 밝기가 이미 보일까 말까 한 자리에 있으면 파도의 골에서 점이 사라집니다.** 위 표의 0 두 줄과 845 한 줄이 같은 파도의 마루와 골입니다.

### 2.3 원인 둘: 서울의 구간이 배경에서 가장 시끄러운 구간입니다

서울이 서 있는 y 1,757 ~ 4,795 동안 화면 한가운데에는 이것들이 같이 있습니다.

- 수면과 지평선 (y 2,880까지 살아 있음)
- 해와 반사 기둥 (화면 세로 한가운데를 관통)
- 파문 고리 (같은 구간에서 가장 밝고 큼)

서울은 화면 가로의 52%를 차지하고 중앙에 섭니다. **위 셋과 정확히 같은 자리입니다.** 싱가포르의 구간에는 물도 해도 없고 고리도 잦아듭니다. 같은 밝기의 점이라도 한쪽은 밝은 것 위에, 한쪽은 빈 화면 위에 놓입니다.

### 2.4 원인 셋: 서울이 더 성깁니다

같은 1,990점으로 그리는데 윤곽의 길이가 다릅니다.

| | 화면 폭 | 화면 크기 | 모양 |
| --- | --- | --- | --- |
| 서울 | 52% (748px) | 748 × 613 | 둥글고 들쭉날쭉 |
| 싱가포르 | 67% (971px) | 971 × 496 | 납작하고 길쭉 |

서울의 윤곽선 길이가 더 길어서 같은 점 수로 그리면 점 사이가 더 벌어집니다. 게다가 싱가포르는 `calm` 때문에 밝기가 0.6배로 낮은데도 더 잘 읽힙니다. 밝기 값이 아니라 **점 밀도와 경쟁 상대**가 갈랐습니다.

## 3. 고치기

### 3.1 [P0] 파도가 점을 지우지 못하게 합니다

`lib/background/config.ts`:

```ts
  // 2026-09-23 (서울 존재감 브리프 2.2): 0.3 → 0.12. ±30%는 밝기에 여유가 있을 때
  // "살아 있는 선"이지만, 기준 밝기가 보일까 말까 한 자리면 파도의 골에서 점이
  // 사라집니다. 스크롤을 고정해 놓고 잰 열 프레임 중 두 프레임에서만 서울이
  // 읽혔습니다. 파도는 남기되 골이 바닥에 닿지 않게 합니다.
  waveAmp: 0.12,
```

그리고 셰이더에서 파도에 바닥을 둡니다. 값이 아무리 낮아도 0.8 아래로 내려가지 않습니다.

```glsl
  // 2026-09-23: 파도의 골에 바닥. 마루는 그대로 두고 골만 올립니다.
  float wave = max(1.0 + uWave.y * sin(6.2831853 * (aPhase - uTime / uWave.x)), 0.8);
```

### 3.2 [P0] 서울의 점을 촘촘하게

윤곽이 길어서 성깁니다. 점 수가 아니라 **점 크기**로 메웁니다. 점 수를 늘리면 폰의 성능 예산을 건드리게 됩니다.

```ts
  // 2026-09-23 (서울 존재감 브리프 2.4): 서울은 윤곽선이 길어 같은 1,990점으로도
  // 싱가포르보다 성깁니다. 두 형상이 같은 점 크기를 쓰던 것을 형상별로 나눕니다.
  // 싱가포르 값은 지금 화면에서 잘 읽히므로 그대로입니다.
  edgePxLandscapeSeoul: 5.0,   // 싱가포르는 4.2 그대로
  edgePxSeoul: 3.8,            // 폰. 싱가포르는 3.2 그대로
```

`setShapeLook`에 지금 넘기는 `edgePx`를 `morph`로 보간하세요. `morph`가 0이면 서울 값, 1이면 싱가포르 값입니다. 건너는 동안 자연히 이어집니다.

### 3.3 [P0] 경쟁을 없앱니다

이 항목은 `docs/background-one-clock-brief.md` 3.3과 3.4가 이미 다룹니다. **그 브리프를 먼저 실행하면 이 항목은 공짜로 해결됩니다.**

- 수면이 다 가라앉은 뒤에 서울이 섭니다(한 번에 한 장면).
- 파문 고리가 사건에 묶여, 서울 구간 한가운데에서는 잔물결만 남습니다.

두 브리프를 따로 실행한다면 이 브리프를 나중에 하세요. 순서가 반대면 서울을 밝게 올려 놓고 다시 낮춰야 합니다.

### 3.4 [P1] 서울의 구간을 늘릴 것인가

여기까지 해도 더 길게 보고 싶다면 손잡이는 하나입니다. 건너기의 시작을 뒤로 미룹니다.

```ts
  // 지금: morph: { startVh: 0.5, spanVh: 1.5 }  → #naru 0.5화면 앞에서 시작
  // 대안: morph: { startVh: -0.5, spanVh: 1.5 } → #naru 0.5화면 뒤에서 시작
  morph: { startVh: -0.5, spanVh: 1.5 },
```

데스크톱 기준으로 서울이 3,038px에서 3,938px로 늘고 싱가포르가 3,454px에서 2,554px로 줄어, 비율이 1 : 1.14에서 **1 : 0.65**가 됩니다.

**이건 뜻이 걸린 결정이라 사용자가 정합니다.** 지금은 `#naru` 챕터가 시작되기 전에 이미 싱가포르로 건너기 시작합니다. 뒤로 미루면 "나루"라는 제목을 읽는 동안 아직 서울이 서 있고, 그 챕터가 그룹의 싱가포르 뿌리를 설명하는 대목에서 싱가포르가 도착합니다. 저는 뒤로 미루는 쪽이 낫다고 보지만, 3.1~3.3만으로 충분할 수 있으니 **먼저 그것부터 배포하고 실제 화면을 보고 정하세요.**

## 4. 절대 하지 말 것

- **점 개수를 늘리지 마세요.** `points: { phone: 1100, desktop: 1990 }`은 구운 파일에 있는 전부이자 폰의 성능 예산입니다. 메우는 것은 점 크기입니다.
- **`edgeBright`와 `innerBright`를 올리지 마세요.** 본문 흰 글자의 대비가 이 값에 걸려 있습니다. 3.1~3.3으로 먼저 해결하고, 그래도 모자라면 그때 재세요.
- **싱가포르의 점 크기(`edgePxLandscape` 4.2, `edgePx` 3.2)를 바꾸지 마세요.** 지금 잘 읽힙니다. 바뀌는 것은 서울 값과 그 사이 보간뿐입니다.
- **`landscapeW` 0.52와 `portraitW`, `singaporeW` 0.66을 바꾸지 마세요.** 9월 19일에 양쪽 화면에서 맞춘 값입니다.
- **`wavePeriod` 12초를 바꾸지 마세요.** 바꾸는 것은 진폭과 바닥입니다.
- `crossing`과 `field` 변형을 건드리지 마세요. `/2026-08`이 `field`를 씁니다.
- em dash 금지. 결정은 `DECIDED 2026-09-23` 한국어 주석으로.

## 5. 검증

캔버스만 보려면 DOM을 지우지 말고 `header,main,footer`의 `opacity`를 0으로 낮추세요. 지우면 배경이 함께 사라집니다.

**시간에 따라 변하는 것을 재고 있으므로, 한 지점에서 한 장만 찍으면 안 됩니다.** 각 지점에서 0.8초 간격 10프레임을 찍고 최솟값과 중앙값을 함께 보세요.

| # | 항목 | 기준 |
| --- | --- | --- |
| 1 | 깜빡임 | y 2,800 고정 10프레임에서 서울 점 픽셀의 **최솟값이 중앙값의 60% 이상** (지금 최솟값 0, 중앙값 약 90) |
| 2 | 서울 구간 전체 | 서울 온전 구간을 8지점으로 나눠 각 지점 10프레임의 중앙값을 낼 때, **모든 지점에서 싱가포르 구간 중앙값의 50% 이상** (지금 1~9%) |
| 3 | 알아보기 | 그 8지점을 사람이 볼 때 서울로 읽힘. 밝기를 올리지 않은 원본으로 판단 |
| 4 | 싱가포르 불변 | 싱가포르 구간 8지점의 중앙값이 적용 전과 **±15% 이내** |
| 5 | 본문 대비 | 서울 구간의 `#december`·`#gains` 본문 흰 글자가 배경 대비 **4.5:1 이상**. 실패하면 배포하지 말고 보고 |
| 6 | 두 화면 | 1~5번을 1440×900과 390×844에서 각각 |
| 7 | 건너는 중 | 점 크기 보간이 끊기지 않음. 건너기 구간 6지점에서 점 크기가 단조롭게 변함 |
| 8 | 모션 민감 | `prefers-reduced-motion: reduce`에서 파도가 멈추고, 멈춘 자리의 밝기가 0.8 아래로 내려가지 않음 |
| 9 | 아카이브 | `/2026-08` 배경이 적용 전과 픽셀 차이 없음 |
| 10 | 프레임 | 폰에서 초당 프레임이 적용 전보다 10% 넘게 떨어지지 않음 |
| 11 | em dash | 0건 |

**1번과 2번이 이 브리프의 전부입니다.** 시간을 늘리는 것이 아니라 있는 동안 보이게 하는 것입니다.
