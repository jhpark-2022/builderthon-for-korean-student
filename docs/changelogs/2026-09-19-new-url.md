# Changelog 2026-09-19 (주소를 naru-crossing-seoul로 옮긴다)

**Project:** 나루 NARU 사이트 (Next.js)
**Branch:** `main`
**Scope:** Vercel 프로젝트 이름과 주소, 코드 안에 박혀 있던 옛 주소 다섯 곳. 화면 카피와 레이아웃은
건드리지 않았습니다.

## 1. 한 것

사용자: "링크도 빌더톤이 아니고, 나루, 크로싱 서울이어야 함." 이름은 물어서 정했습니다
(`naru-crossing-seoul`: 그룹과 이벤트를 다 담고, 링크만 보고도 무엇인지 압니다).

- Vercel 프로젝트 이름 `builderthon-for-korean-student` → `naru-crossing-seoul`.
- 새 주소: **https://naru-crossing-seoul.vercel.app**
- 코드 안의 옛 주소 다섯 곳을 고쳤습니다.
  `app/layout.tsx`의 `SITE_URL`(공유 카드의 `metadataBase`와 정규 주소), `app/sitemap.ts`,
  `app/robots.ts`, `components/Quiz.tsx`의 공유 링크 폴백 호스트, `components/journey/Journey.tsx`의 주석.

### 이름만 바꿔서는 주소가 열리지 않았습니다

프로젝트 이름을 바꿔도 `naru-crossing-seoul.vercel.app`은 404였고, 옛 주소가 그대로 200이었습니다.
배포 보호(`ssoProtection: all_except_custom_domains`)가 켜져 있어서, **프로젝트의 프로덕션 별칭이 아닌
주소는 전부 Vercel 로그인으로 넘어갑니다.** 이름을 바꾼 뒤에도 프로덕션 별칭은 옛 주소였어요.

순서는 이렇게 했습니다.

1. `vercel project rename builderthon-for-korean-student naru-crossing-seoul`
2. `vercel alias set <최신 프로덕션 배포> naru-crossing-seoul.vercel.app` — 이 단계까지는 새 주소가
   SSO로 302.
3. `vercel alias rm builderthon-for-korean-student.vercel.app` — 옛 별칭을 떼자 새 주소가 프로덕션
   별칭이 되고 200.

배포 보호 설정은 **건드리지 않았습니다.** 미리보기 배포는 여전히 로그인 뒤에 있습니다.

## 2. 검증

| 주소 | 결과 |
| --- | --- |
| `naru-crossing-seoul.vercel.app/` | 200 text/html |
| `/2026-08` | 200 |
| `/quiz` | 200 |
| `/naru/naru-manifesto-v1-2026-09.pdf` | 200 application/pdf |
| `/opengraph-image` | 200 image/png |
| `/sitemap.xml`, `/robots.txt` | 200, 새 주소로 갱신됨 |
| `og:url`, `og:image` | 새 주소 |
| 옛 주소 | 404 (더 이상 이 프로젝트의 것이 아닙니다) |

## 3. 남은 것

- **옛 주소로 공유된 링크는 전부 끊깁니다.** 텔레그램·카카오·슬랙의 미리보기, 메일에 넣은 링크,
  오픈채팅 공지에 적힌 주소. 새 주소로 다시 공유해야 합니다.
- 구글에 색인된 옛 주소도 사라집니다. `sitemap.xml`이 새 주소로 갱신되었으니 다시 제출하면
  됩니다(Search Console에 등록해 둔 것이 있다면).
- 진짜 도메인(naru.kr 같은)을 사면 `SITE_URL` 한 줄만 바꾸고 Vercel에 연결하면 됩니다. 그때는 이
  `.vercel.app` 주소를 리다이렉트로 남겨 둘 수 있습니다.
- GitHub 레포 이름(`builderthon-for-korean-student`)은 그대로입니다. 바꾸려면 말씀해 주세요.
  리모트 주소가 바뀌므로 로컬에서 `git remote set-url`이 한 번 필요합니다.
