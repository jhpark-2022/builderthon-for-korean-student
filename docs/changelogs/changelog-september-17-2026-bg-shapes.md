# Changelog 2026-09-17 (배경: 기슭의 입자를 싱가포르와 서울 형상으로)

**Project:** 나루 NARU 사이트 (Next.js)
**Branch:** `main`
**Scope:** 나루 홈(`/`)의 배경 `variant="crossing"`에서 **기슭 두 곳의 입자 초기 분포**만.
국면, 등불, 반사 띠, 블룸 임계값, 품질 티어는 그대로. `/2026-08`은 손대지 않았습니다.
브리프는 `docs/background-shapes-brief.md`.

## 1. 문제

같은 날의 "건너는 점들" 배경에서 기슭의 입자는 양옆 30%에 이봉 가우시안으로 흩어져
있었습니다. 어느 쪽이 어디인지 화면이 말해 주지 않았습니다. 사이트의 이름이 크로싱
서울이고 8월이 싱가포르였으니, 첫 화면에서 왼쪽 기슭이 싱가포르, 오른쪽 기슭이
서울로 읽혀야 합니다.

## 2. 결정

기슭의 입자를 **왼쪽은 싱가포르 본섬, 오른쪽은 서울특별시 경계** 윤곽 위에 세웁니다.
점만 씁니다(외곽선 없음, 면 없음, 주황 점 없음). 스크롤하면 지금처럼 풀려서 강을
건넙니다.

### 형상 원본과 굽기

| | 싱가포르 | 서울 |
| --- | --- | --- |

| 원본 꼭짓점 | 21 | 7,700 |
| 단순화 | 없음(로고와 같은 정도) | Douglas-Peucker → **64 꼭짓점**(목표 60~90). 경도에 cos(위도) 보정 |
| 점 수 | **2,000** (가장자리 1,571 / 속 442) | **2,000** (가장자리 1,551 / 속 449) |

`scripts/build-shape-points.py` 하나가 둘을 굽습니다. 512×512 래스터 → 바운딩 박스
너비의 **6%** 안쪽 띠는 밀도 **3배** → 푸아송 디스크(Bridson, 속 반지름 = 가장자리
반지름 × √3) → 이진 탐색으로 2,000점 → **가장자리 먼저, 속 나중** 순서로
`lib/background/shapes/{singapore,seoul}.ts`에 숫자 리터럴 `Float32Array`([x, y, edge] ×
2,000, 바운딩 박스를 [-1, 1]에 맞춤). 런타임에 SVG나 GeoJSON을 읽지 않습니다. 한강은
같은 출처에 하천 폴리곤이 없어 넣지 않았습니다(지어낸 강 금지).

### 장면

- **기울기 18°**(x축). 탁자 위의 지도처럼. 3° 포인터 패럴랙스에서 입체가 살면서 위에서
  본 윤곽으로 읽힙니다. z 두께는 형상 너비의 ±15%. 두 형상은 화면에서 같은 너비
  (실제 크기 비율 무시).
- **자리는 DOM에서 잽니다** (`lib/background/utils/shapeLayout.ts`). 브리프의 자리
  (x 22%/78%, y 55%, 카피 뒤 40% 감광)로 먼저 만들었는데, 싱가포르는 히어로 카피
  글자 뒤에 묻혀 보이지 않았고 서울은 카운트다운 패널의 유리에 반쯤 가려졌습니다.
  실제 화면(2000×881)을 본 판단: "배경에 서울과 싱가폴이 보이지 않는다". 그래서
  히어로에 앵커 셋을 두고(`data-shape-anchor`: 카피 단의 CTA 줄, 패널 카드, 폰의 띠)
  그 사각형을 재서 빈자리에 세웁니다. 배경(월드 좌표)과 DOM 라벨이 같은 함수를 씁니다.
  - **데스크톱(lg 이상)**: 싱가포르는 CTA 줄 아래, 서울은 패널 카드 아래. 둘 다 같은
    밑선(뷰포트 아래 40px 위)에 서고 너비는 24%까지, 두 빈 띠 중 얕은 쪽에 맞춥니다.
    1440×900에서 337px, 1440×800에서 265px. 감광 없음.
  - **얕은 노트북 화면(1280×720, 1366×768)**: 너비를 16% 아래로 줄이지 않고, 카피·
    패널과 겹치는 윗부분만 40%로 감광합니다(감광 사각형 = CTA 줄 아래선 위의 카피
    단, 패널 카드). 형상의 아래 대부분은 빈 띠에 남아 읽힙니다.
  - **폰(lg 아래)**: 히어로가 625px에서 끝나 빈 띠가 없었습니다. 브리프의 "위아래로
    쌓기"(y 35%/70%)는 카피 뒤에 묻혔습니다. **사용자 결정 2026-09-17: CTA 아래에
    150px 띠를 추가**하고 두 형상을 나란히(각 너비 38%, x 27%/73%) 세웁니다. 폰
    페이지가 158px 길어져 ko 12,550px(8월 문법 브리프의 상한 12,500을 50px 넘음.
    감수한 결정).
  - 앵커가 하나도 없으면 브리프의 자리(`SHAPES.landscape/portrait`)로 돌아갑니다.
- **등불**: 가로 화면은 그대로. 세로 화면은 왼쪽(uv x 0.2)에서 **가운데**로. 띠의 두
  형상 사이 틈(강)이고, 높이가 CTA 버튼보다 아래라 반사 기둥이 버튼을 지나지 않습니다.
- **라벨** `SINGAPORE` / `SEOUL`: DOM 텍스트(`components/home/NaruHome.tsx`의
  `ShapeLabels`), 11px 대문자 자간 `text-white/40`, 형상 아래 10px 가운데 맞춤(fixed).
  스크롤 0.5·뷰포트까지 선형으로 사라지고 그 뒤에는 렌더하지 않음. `{ko, en}` 둘 다
  영문.
- **국면**: banks에서 형상 그대로(드리프트 진폭은 이전의 30%: 드리프트 0.75배, 숨 0.12).
  gather는 **속 점부터 움직이고 가장자리 점이 마지막에** 떠나도록 `aRank`(구운 순서)로
  지연을 줍니다(가장자리 최대 55% + 난수 15%). crossing 이후는 이전 그대로. 정지
  토글에서는 banks로 얼어 형상 둘이 정지 화면입니다.
- **밝기**: 기슭 불투명도가 품질 티어의 `intensity`와 곱해지지 않게 바꿨습니다(폰
  450점 × 0.6 × 40%에서는 형상이 보이지 않았음). gather부터는 이전처럼 `intensity`가
  들어갑니다. 점 크기 1.6 → 1.9.

## 4. 측정

### 알아보기 (브리프 6-2, 6-3)

`.shots/naru/bg-shapes/compare-shapes.png`: 행마다 원본(로고 섬 / KOSTAT 경계 7,700
꼭짓점) · 구운 점 · 1440 정지 화면 · 390 정지 화면(450점). 왼쪽은 라벨 없이 로고
심볼과 같은 윤곽으로 읽히고, 오른쪽은 서울 경계 지도 옆에 두면 같은 윤곽입니다. 폰
450점(가장자리 먼저 순서라 전부 가장자리 점)에서도 윤곽이 남아 가장자리 가중을 4배로
올리지 않았습니다. 전체 화면은 `paused-1440.png`, `paused-390.png`(정지 토글, 스크롤 0).
움직임을 켠 실제 상태(창 있는 Chrome, 20초 뒤)는 `motion-1440x900.png`, `motion-1440x800.png`,
`motion-1280x720.png`, `motion-2000x881.png`, `motion-390x844.png`. 형상은 20초 뒤에도
흐트러지지 않습니다(컬 노이즈 드리프트 ≤ 0.5 월드 단위, 형상 반폭 6~7).

### 카피 뒤 휘도 (브리프 6-4)

본문을 숨기고 캔버스만 찍어 평균 상대 휘도.

| 자리 | 형상 전(9/17 crossing) | 형상 후 |
| --- | --- | --- |
| 1440 히어로 H1 뒤 [72,230,660,390] | 0.0045 | **0.0043** |
| 1440 코어 판 뒤 | 0.0054 | 0.0055 |
| 390 히어로 H1 뒤 [20,120,370,330] | 0.0037 | **0.0037** |
| 390 코어 판 뒤 | 0.0059 | 0.0075 |

형상이 카피 뒤에 있던 중간 단계에서는 390 H1 뒤가 0.0044(브리프의 y 35%)였고, 지금은
형상이 카피와 겹치지 않아 이전 값과 같습니다.
390 코어 판 뒤가 0.0059 → 0.0075로 오른 것은 세로 화면의 등불이 왼쪽에서 가운데로
와서 그 판 뒤에 등불 반사가 들어오기 때문입니다. 8월 히어로 H1 뒤(0.0122)보다는
낮습니다(crossing 체인지로그의 대비 기준).
