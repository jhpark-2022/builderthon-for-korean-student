## 2. 카운트다운: 상자를 채운다

사용자: "시간 타이머가 좀 더 박스를 꽉 채워주면 좋을 것 같아."

전에는 flex라 숫자 셋이 왼쪽에 몰리고 상자의 오른쪽 절반이 비어 있었습니다.

- 행을 격자로 바꿨습니다. `sm`부터 라벨 한 칸 + 일·시간·분 세 칸이 같은 너비(`1fr`)로 펴집니다.
- 숫자 크기 1.6rem → 1.75rem(폰) / 2.25rem(sm+). 패널 안쪽 여백도 한 단 키웠습니다.
- **폰에서도 시간까지 보입니다.** 전에는 일 하나였고 그 한 칸이 상자의 40%에서 끝났습니다.
  분은 그대로 `sm`부터입니다(390px에서 세 칸이면 숫자를 줄여야 합니다).
- 실측: 1440px에서 패널 614×166, 390px에서 336×139, 가로 오버플로 없음.

## 3. 스크롤 리빌: 8월 페이지와 같은 효과를 홈에도

사용자: "맨 위에서 스크롤해서 아래로 내릴 때 뭔가 애니메이션이 있으면 좋겠어, 8월 페이지에서 쓴
같은 효과로."

### 먼저 찾은 것: 그 효과는 8월 페이지에서도 거의 작동하지 않고 있었습니다

`app/globals.css`의 리빌 안전망이 조건 없이 걸려 있었습니다.

```css
[data-chapter-reveal] { animation: chapterFailsafe 1ms linear 1.5s forwards; }
```

CSS 애니메이션은 인라인 스타일을 이기므로, **1.5초가 지나면 화면 밖 챕터까지 전부 보이는 상태로
굳습니다.** 실측: `/2026-08`을 열고 3초 뒤, 스크롤 0에서 17,342px 아래의 챕터가 이미 opacity 1.
`Chapter.tsx` 안의 1200ms 폴백도 조건 없이 전부 보이게 하고 있었어요. 리빌은 첫 1.5초 안에 화면에
들어온 것에만 걸렸고, 안전망이 기능을 대체하고 있었습니다.

### 고친 방법

- `Reveal`과 `Chapter`가 마운트되면 `<html>`에 `js-reveal-ready`를 답니다.
- CSS 안전망을 `html:not(.js-reveal-ready) [data-chapter-reveal]`로 좁혔습니다. 번들이 죽으면
  (클래스가 없으면) 1.5초 뒤 본문을 보여 주는 보호는 그대로입니다.
- 두 컴포넌트의 1200ms 폴백을 **화면 안에 있는 경우로** 좁혔습니다. 안전망이 원래 하려던 일
  ("이미 화면에 있는데 관찰자가 울리지 않는 경우")은 그대로 지키고, 화면 밖은 건드리지 않습니다.

### 홈에 단 것

`components/shared/Reveal.tsx` 하나를 새로 만들고, `Chapter`의 효과값을 **그대로** 씁니다
(opacity 0 → 1, translateY(40px) → 0, 700ms ease-out, 한 번만). 두 페이지가 한 사이트로 읽히려면
움직이는 방식이 같아야 합니다.

홈도 같은 `Chapter`를 쓰고 있었지만 챕터가 다섯이고 하나가 3,000px입니다. 챕터에 들어서는 순간
한 번 나타난 뒤로는 화면 몇 개 분량을 아무 일 없이 내려가게 됩니다. 그래서 챕터 **안의** 블록
열일곱에 같은 효과를 달았습니다: 숫자 둘, 노선도, 데이 카드, 아쉬웠던 넷, 끝나면 할 일, 얻는 것
다섯, 8월이 남긴 것, 코어 둘, 경첩, 마지막 줄, 3층 다이어그램, 문 셋, 결핍 세 칸, 공통 조건,
안전장치, 닫는 문단, 매니페스토.
