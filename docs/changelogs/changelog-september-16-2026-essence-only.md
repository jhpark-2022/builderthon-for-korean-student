## 추가 (같은 날) · 사진이 삐져나오던 것을 고칩니다

### 무슨 일이 있었나

사진 벽이 CSS `columns`였습니다. 어떤 사진도 자르지 않으려고 고른 방식이었어요.
그런데 세로로 찍힌 사진이 셋 섞여 있었습니다. 열 너비 372px에서

| | 렌더 높이 |
| --- | --- |
| 가로 사진 (4:3) | 279px |
| 세로 사진 (3:4) | 496px |

**1.8배**입니다. `columns`는 열 높이를 맞추려 하지만 맞출 수 있는 단위가 사진 한
장이라, 높이가 제각각인 열 장을 세 열에 나누면 어느 조합으로도 딱 떨어지지
않습니다. 실측하니 가운데 열이 양옆보다 **221px** 짧았어요. 벽이 아니라 몇 장이
아래로 삐져나온 것처럼 보였습니다.

lazy 로딩 중에는 더 심했습니다. 아직 받지 않은 사진의 높이를 브라우저가 모르는
동안 열 균형이 계속 다시 잡히거든요.

### 어떻게 고쳤나

화면에서 자르는 대신 **원본을 전부 4:3으로 맞춰 두고** 균일한 grid에 넣습니다.
자르는 자리를 런타임의 `object-cover`가 고르게 두지 않고 사람이 골랐습니다.

- 세로 셋(`day1-checkin` · `day1-listen` · `day1-crowd`)과 16:9였던
  `day5-session`을 Dropbox 원본에서 4:3으로 다시 잘라 재출력했습니다. 객석
  사진은 아래쪽에 사람이 몰려 있어서 세로 중심을 0.65로 내렸고, 나머지는
  가운데입니다.
- `PhotoWall`이 `columns` → `grid grid-cols-2 lg:grid-cols-3`. 각 칸은
  `aspect-[4/3]`이고 이미지는 `fill` + `object-cover`입니다.
- 지금 열두 장 전부가 정확히 4:3이라 `object-cover`는 **아무것도 자르지
  않습니다.** 4:3이 아닌 원본이 나중에 들어올 때를 대비한 안전망으로만 있어요.

**이 배치에서는 한 장도 삐져나올 수 없습니다.** 모든 칸이 같은 크기입니다.
실측: 열두 칸 전부 372x279, 세 열의 바닥이 전부 2745px.

### 장수는 6의 배수로

시상식 두 장을 뺀 뒤 열 장이었는데, 3열에서 마지막 줄에 한 장만 남았습니다.
데스크톱 3열과 그 아래 2열 양쪽에서 마지막 줄이 꽉 차는 수는 6의 배수뿐이에요
(3x4, 2x6). 그래서 같은 날의 커리어 간담회(`day8-panel`)와 트랙 공유회
(`day8-watch`) 사진으로 채워 다시 열두 장입니다. 늘리거나 줄일 때 이 규칙을
지키세요.

`RecordPhoto`의 `width`/`height`는 이제 화면이 읽지 않습니다(`fill`을 씁니다).
어떤 원본이 들어와 있는지를 남겨 두는 기록이에요. 4:3이 아닌 숫자가 보이면 그
사진은 잘려서 그려지고 있다는 뜻입니다.

### 배경: 깊은 물 (`shaders/water.ts`)

수면이 스크롤 30%에서 가라앉고 나면 화면에 밤의 남색만 남았습니다. 페이지의
나머지 70%에는 배경이 없는 것과 같았어요. 히어로에서 한 번 보여 주고 물러나는
것과, 읽어 내려가는 동안 아무 일도 일어나지 않는 것은 다릅니다.

가라앉은 자리를 **깊은 물** 층이 받습니다. 세 가지만 있어요.

| | 무엇 |
| --- | --- |
| 물살 | 위에서 아래로 흐르는 아주 옅은 띠 |
| 링 | 점을 중심으로 계속 퍼지는 파문 |
| 점 | 그 한가운데의 주황 점 |

**링과 점이 로고입니다.** 머리의 마스터 로고 한가운데에 링과 주황 점이
있고(`public/naru/naru-master-rev.png`), 히어로를 지나 로고가 화면 밖으로 나가면
같은 표식이 물 아래에서 스크롤을 따라 내려옵니다. 위에서는 건너편의 등불이고
아래에서는 물속의 빛이에요. 배경과 로고가 같은 것을 말하게 하는 연결선입니다.

### 스크롤이 물살을 젓습니다 (`uFlow`)

`BackgroundScene`이 스크롤 속도를 재서 0..1로 넘깁니다. 빠르게 스크롤하면 물살
띠가 세로로 늘어나고(주파수 3.4 → 1.2) 파문이 빨라집니다.

감쇠 계수가 비대칭인 것이 요점입니다. 손가락이 움직이면 즉시 반응하고(12),
멈추면 서서히 잦아듭니다(1.8). 대칭이면 스크롤을 멈춘 순간 배경도 뚝 멈춰서,
물이 아니라 스위치로 보입니다.

모션 민감 설정에서도 `uFlow`는 끄지 않습니다. 자동으로 시작되는 움직임이 아니라
손가락이 만든 것이라 WCAG 2.2.2의 대상이 아니에요(`applyReducedMotion`의 기존
기준과 같습니다). 물살과 파문에 `uScroll`이 들어 있는 것도 같은 이유입니다 —
`uTime`이 멈춰도 스크롤하면 흐릅니다.

### ⚠️ 대비

여기가 이 셰이더에서 가장 위험한 자리입니다. 본문 **전 구간**의 진짜 배경이 이
층이라, 값을 올리면 흰 글자의 대비 하한이 통째로 무너집니다(2026-09-15 접근성
감사 S-4). 지금 값의 휘도 기여는 물살 약 0.01, 링 약 0.05, 무리 약 0.03입니다.

점의 자리도 대비 때문입니다. 등불의 세로줄에서 더 왼쪽(`lx - 0.09`)이고,
스크롤을 따라 내려와 한 자리에 머무르지 않습니다. 가운데에 두거나 멈춰 두면 어느
문단 뒤에 주황 점이 박힌 채로 그 문단을 읽게 됩니다.

올리기 전에 실제 화면에서 본문 글자와의 대비를 다시 재세요.

실행해 보지 못했습니다.

| `mt-6` | 27px | 제목 → 리드 문장. 앞 블록에 붙는 띠. |
| `mt-12` | 54px | 블록 → 블록. **기본값.** 의심스러우면 이것 |
| `mt-24 sm:mt-32` | 108/144px | 부속으로 강등. `#why`의 exec 하나뿐 |

카드나 다이어그램 **안쪽** 간격은 이 스케일을 따르지 않습니다. 저긴 한 덩어리의
내부 조판이고, 스케일은 덩어리와 덩어리 사이의 것입니다.

### 고친 자리

- 히어로: `mt-7`(이 파일의 유일한 값) → `mt-6`, `mt-8` → `mt-6`,
  `mt-6 sm:mt-9`(역시 유일) → `mt-12`
- `#record` · `#how`: 이음매 오버라이드 제거
- `#december`: 스테이지만 `mt-14`였던 것 → `mt-12`, 날짜 줄 `mt-5` → `mt-6`,
  ctaNote `mt-10` → `mt-12`
- `#why`: 코어 `mt-14 sm:mt-16` → `mt-12`, 서명 헤어라인 `mt-8` → `mt-6`,
  agenda `mt-14` → `mt-12`. note는 코어 둘의 결론이라 `mt-10` → **`mt-6`**으로
  붙였습니다.

검증: 챕터 직계 자식의 간격이 전부 네 값 중 하나, 이음매는 216 / 270 / 306
세 단계, 가로 넘침 0. 스케일은 `NaruHome.tsx` 위쪽 주석이 정본입니다.

## 추가 (같은 날) · 번호 줄을 없앱니다

카드 맨 위에 번호가 한 줄 서고 그 아래에 내용이 오는 꼴이 세 군데 있었습니다.
`#why`의 코어(`01` `02`), `#why`의 exec(`i` `ii`), `#december`의 스테이지
(`00`~`04`).

**그 줄이 하는 일이 없었습니다.**

- 개수는 세어 줄 필요가 없습니다. 칸이 둘이면 둘, 다섯이면 다섯인 걸 보면 압니다.
- 순서는 `<ol>`이 이미 나릅니다. 번호는 셋 다 원래 `aria-hidden`이었어요.
  보조기술에는 처음부터 없던 것입니다.
- 스테이지는 바로 아래 `when`("본 일정 전", "1일차"...)이 순서를 글로 말합니다.
  번호가 그걸 한 번 더, 그것도 어긋나게 말하고 있었어요. 화면은 `00`부터 세는데
  `<ol>`은 1부터 셌습니다.

없어도 되는 것에 줄 하나씩을 주고 있었습니다. 가려야 하는 것은 대개 없어도 되는
것입니다.

### 그래서

| | 전 | 후 |
| --- | --- | --- |
| `#why` 코어 | 번호 / 제목 / 본문 / 지키는 것 | 제목 / 본문 / 지키는 것 |
| `#why` exec | 번호 / 제목 / 본문 | 제목 / 본문 |
| `#december` 스테이지 | 번호 / 이름 / 언제 / 무슨 일 | 이름 / 언제 / 무슨 일 |

나루 점은 남깁니다. 로고와 배경을 잇는 선이라서요. 대신 **자기 줄을 갖지 않고
제목의 첫 글자 앞에 섭니다.**

크기를 `0.75em`으로 둔 것은 `H3`이 clamp라 24.3~34.2px 사이에서 움직이기
때문입니다. px로 박으면 좁은 화면에서 점이 제목보다 커져요. `0.75em`이면
18.2~25.6px이고, 로고 가이드의 하한 18px을 좁은 쪽 끝에서 정확히 지킵니다.
더 줄이지 마세요. 링이 지름의 5/26이라 그 아래로는 1× 화면에서 흐린 후광으로
뭉갭니다.

`stage.when`은 번호가 비운 자리를 이어받아 `text-white/50` → `text-accent`가
됐습니다. 순서를 나르는 유일한 줄이 된 만큼 눈에 띄어야 하고, 대비도 4.96:1에서
6.32:1로 올라갑니다.

`core.index` · `item.index` 키는 `data/naru.ts`에 그대로 있습니다.
