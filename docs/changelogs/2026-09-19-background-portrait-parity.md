## 1. 원인

브리프 2장이 맞았습니다. 폰에서 배경이 달라 보인 것은 품질이 아니라 **세로 화면에서 수면이 아예
그려지지 않았기** 때문입니다.

```glsl
float mask = max(smoothstep(H - 0.004, H + 0.004, p.y), portrait);
vec3 col = mix(water, sky, mask);
```

`portrait`가 1이면 `mask`가 화면 전체에서 1이고 `mix(water, sky, 1.0)`은 `sky`입니다. `water`는
계산만 되고 한 픽셀도 쓰이지 않았습니다. 같은 `portrait`가 지평선 빛, 파문 링, 나루 점도 껐습니다.

그렇게 껐던 이유(9/18: 폰에서 링이 거대한 고리로 보임)도 진단이 반만 맞았습니다. 이 셰이더의
가로 거리는 화면 **높이** 단위라, 같은 반지름이 1440×900에서는 가로의 26%를, 390×844에서는 91%를
덮습니다. 고칠 자리는 반지름의 기준이지 켜고 끄는 스위치가 아니었습니다.

## 3. 검증

캡처는 `.shots/parity/`에 있습니다(레포에 커밋하지 않습니다). 이 환경의 Chrome은
`prefers-reduced-motion: reduce`를 기본으로 보고하므로, 모션이 필요한 항목은 `matchMedia`를
가로채 모션을 켠 상태로 다시 쟀습니다.

**배경만 따로 재는 캡처를 추가했습니다.** 브리프의 기준값은 DOM이 보이는 캡처에서 나왔는데, 폰의

### 9번을 코드로도 확인했습니다

바뀐 네 표현은 가로 화면(`uAspect ≥ 1` → `portrait = 0`)에서 전부 항등입니다.

- `max(smoothstep(…), 0.0)` = `smoothstep(…)` (smoothstep의 치역은 [0,1])
- `… * (1.0 - 0.0)` = `…` (지평선 빛, 링, 점 세 곳)
- `K = mix(1.0, …, 0.0)` = `1.0` → `0.075 / 1.0`, `2.4 * 1.0`, `0.10 / 1.0`
- `config.ts`의 변경은 `SEOUL_WATERMARK.portrait.*`와 폰 티어뿐이고, 노트북·데스크톱 티어와
  `landscapeW`·`points.desktop`은 그대로입니다
- `PostFX`의 새 인자는 기본값이 종전 상수(0.6)이고, `crossing`·`field`는 값을 넘기지 않습니다

## 5. 남은 것

- 폰 히어로에서 수면은 화면 아래 31%에 있고, 그 자리를 카운트다운 패널과 사진 넷이 덮습니다.
  배경은 제대로 그려지지만 눈에 보이는 면적은 데스크톱보다 작습니다. 이건 DOM 레이아웃의 문제라
  이 브리프의 범위가 아닙니다(`docs/background-portrait-parity-brief.md` 4장).
- 실기기 프레임은 재지 못했습니다. 떨어진다면 브리프 3.6대로 `bloomIntensity`(0.42)를 먼저
  낮추고, 그래도 안 되면 폰 티어의 `bloom`을 `false`로 되돌리세요. `particles`와 `dprMax`는
  마지막까지 건드리지 마세요.
- 링은 분석으로만 확인했습니다. 실제로 커 보이면 `K`의 상한(2.4)을 올리는 것이 브리프의 지시입니다.
