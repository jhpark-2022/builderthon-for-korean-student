# Changelog 2026-09-19 (데스크톱에서 서울 윤곽이 보이게)

**Project:** 나루 NARU 사이트 (Next.js)
**Branch:** `main`
**Scope:** `lib/background/config.ts`의 `SEOUL_WATERMARK` 세 값과 `BackgroundScene`의 호출 한 줄.
셰이더, DOM, 카피, 라우트는 건드리지 않았습니다.

## 1. 한 것

사용자: "서울의 모습이 데스크톱 버전에서 너무 잘 안 보인다. 모바일은 잘 보인다."

9월 19일의 세로 패리티 작업이 폰의 윤곽을 촘촘하게 만들면서, 이번에는 데스크톱이 상대적으로
성기게 남았습니다. 원인은 셋이고 전부 **밀도**입니다.

| | 데스크톱 (전) | 폰 | 데스크톱 (후) |
| --- | --- | --- | --- |
| 형상 폭 | 뷰포트의 0.58 = 835px | 0.72 = 281px | 0.52 = 749px |
| 점 개수 | 1,400 | 1,100 | **1,990** (구운 파일 전부) |
| 가장자리 점 1개당 윤곽 길이 | 약 2.0px | 약 0.9px | 약 1.2px |
| 점 크기(가장자리/속) | 3.2 / 1.6px | 3.2 / 1.6px | **4.2 / 2.0px** |

- `landscapeW` 0.58 → **0.52**. 같은 점으로 선이 촘촘해집니다.
- `points.desktop` 1,400 → **1,990**. `shapes/seoul.ts`에 구워 둔 점 전부입니다(1,990개가 상한).
  순서가 "가장자리 75% · 속 25%"를 어느 접두사에서도 유지하게 섞여 있어 비율은 그대로입니다.
- **가로 화면 전용 점 크기**를 새로 뒀습니다(`edgePxLandscape: 4.2`, `innerPxLandscape: 2.0`).
  같은 3.2px이라도 폰에서는 폭 281px 형상 위의 3.2px이고 데스크톱에서는 749px 위의 3.2px입니다.
  화면에서 차지하는 비율이 2.7배 차이라, 폰에서 선으로 읽히는 것이 데스크톱에서는 먼지로
  읽혔습니다. 세로 화면은 3.2 / 1.6 그대로입니다.

점을 더 늘리려면 `scripts/build-shape-points.py`의 `N_POINTS`를 올려 다시 구워야 하는데,
그러면 폰이 쓰는 앞부분 1,100점의 배치도 같이 바뀝니다. 폰은 지금이 좋다는 것이 사용자의
말이라 **다시 굽지 않았습니다.**

## 2. 검증

| 항목 | 결과 |
| --- | --- |
| 빌드 | `npm run build` 통과 |
| 데스크톱 1440×900, 스크롤 60% | 윤곽이 끊기지 않는 점선으로 읽힘(`.shots/seoul/d60-try2.png`) |
| 데스크톱 본문 흰 글자 대비 | 12.13:1 → **9.62:1** (배경 상위 0.5% 기준, 기준 4.5:1) |
| **폰 불변** | 같은 조건 캡처의 전/후 차이 17,005화소인데 **같은 코드 재로드 차이가 16,830화소**입니다. 즉 차이는 전부 `ParticleField`의 로드별 난수 지터이고 이번 변경의 결과가 아닙니다 |
| 세로 경로 | `placeSeoul`이 세로에서 `portrait.heroW`를 명시로 넘기므로 `landscapeW`를 읽지 않습니다. `points.phone`과 `edgePx`/`innerPx`도 그대로입니다 |
