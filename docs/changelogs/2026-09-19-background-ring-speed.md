# Changelog 2026-09-19 (세로 화면 파문의 속도)

**Project:** 나루 NARU 사이트 (Next.js)
**Branch:** `main`
**Scope:** `lib/background/shaders/water.ts` 한 줄. 브리프는 `docs/background-ring-speed-brief.md`.
DOM, 카피, `data/naru.ts`, 라우트, 수파베이스는 건드리지 않았습니다. 커밋 `9326bc4`.

## 1. 한 것

```glsl
- float phase = rr * 9.0 - uTime * (0.5 + uFlow * 1.6) - uScroll * 7.0;
+ float phase = rr * 9.0 * K - uTime * (0.5 + uFlow * 1.6) - uScroll * 7.0;
```

세로 패리티(`9d56472`)에서 `K`를 감쇠 `exp(-rr * 2.4 * K)`에만 붙였습니다. 보이는 범위는 2.2배
좁아졌는데 파장과 진행 속도는 그대로였고, 그래서 폰에서는 파문이 좁아진 자리를 예전 속도로
지나갔습니다. 공간 주파수에도 같은 `K`를 곱하면 범위·파장·속도가 한 비율로 움직입니다.

브리프 3.2(uFlow 게인, 파문 중심 이동)는 **하지 않았습니다.** 3.1만 배포하고 실제 폰에서 보고
필요하면 별도 커밋으로 합니다.

## 2. 계산값 (셰이더 식 그대로)

`rr`은 화면 높이 단위이고 픽셀로는 등방입니다. 폰 390×844에서 `K = 1/0.462 = 2.164`.

| | 데스크톱 1440×900 | 폰 (전) | 폰 (후) |
| --- | --- | --- | --- |
| 보이는 범위(감쇠 0.1) | 863px | 374px | 374px (그대로) |
| 파장 | 628px | 589px | **272px** |
| 범위 ÷ 파장 | 1.37개 | 0.64개 | **1.37개** |
| 진행 속도 | 50.0px/s = 가로 **3.5%/s** | 46.9px/s = 가로 **12.0%/s** | 21.7px/s = 가로 **5.6%/s** |
| 범위를 한 번 지나는 시간 | 17.3초 | 8.0초 | **17.3초** |
| 스크롤 1당 이동 ÷ 범위 | 0.81배 | 1.75배 | **0.81배** |

데스크톱 열은 전·후가 같은 값입니다(`K = 1.0`).

## 3. 검증

### 측정 방법을 바꿨습니다 (그리고 왜)

브리프 5장은 0.7초 간격 여덟 장을 요구합니다. **이 환경에서는 불가능했습니다.** 스크린샷 한 장의
왕복이 40~58초라(측정값), 0.7초 간격을 만들 수 없습니다. 대신 같은 값을 더 정확하게 얻는 방법을
썼습니다.

이 Chrome은 `prefers-reduced-motion: reduce`를 기본으로 보고하고, 그때 `motionScale = 0`이라
`uTime`이 0에 고정됩니다. 그러면 파문의 위상이 `rr * 9K - uScroll * 7`이 되어 **마루가 고정된
동심원**이 됩니다. 시간을 쫓을 필요 없이 한 장에서 마루의 반경을 잴 수 있고, 진행 속도는
`각속도 ÷ 공간 주파수`로 바로 나옵니다. 각속도(0.5)는 이번에 건드리지 않았으므로, 공간 주파수의
변화가 곧 속도의 변화입니다.

### 3번: 데스크톱

**코드로는 항등입니다.** 가로 화면에서 `uAspect ≥ 1` → `step(1.0, uAspect) = 1` → `portrait = 0` →
`K = mix(1.0, …, 0.0) = 1.0`(GLSL `mix(x,y,0)`은 정확히 `x`). `rr * 9.0 * 1.0`은 IEEE-754에서
`rr * 9.0`과 같은 비트입니다.

**실측은 노이즈 바닥과 같습니다.** 1440×900, 스크롤 55%, 모션 민감 설정으로 캡처했을 때
전↔후 차이는 34,151화소(2.64%)인데, **같은 코드로 두 번 로드한 후↔후 차이가 34,319화소(2.65%)**
입니다. 서울 워터마크 입자가 로드마다 다른 자리에 뿌려지기 때문입니다. 반경 프로파일(중앙값)로
비교하면 전↔후 평균 차이 0.034, 후↔후 0.037로 같습니다. 즉 매끄러운 층(물·파문·물살)은
바뀌지 않았습니다.

### 폰 전/후 차이가 어디에 있는가

같은 조건(스크롤 55%, `uTime` 고정, 배경만)의 두 장을 빼면 차이가 **반경 40~120px과 240~280px
두 띠에만** 있습니다. 그 사이(160~240px)와 바깥(320px~)은 0.00입니다. 파문의 마루가 옮겨 온
자리 말고는 아무것도 바뀌지 않았다는 뜻입니다.

  (b) 파문 중심의 이동을 절반만 보정하는 두 가지를 **각각 다른 커밋으로** 하세요.

  시간을 얼리고 공간에서 재는 편이 정확합니다. 다음 배경 작업에서도 같은 방법을 쓰세요.
