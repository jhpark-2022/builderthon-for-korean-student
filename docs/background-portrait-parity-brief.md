# 배경 브리프: 세로 화면이 가로 화면을 따라가게 합니다

대상 레포: `website` (커밋 `c54550c` 기준). 바꾸는 파일은 `lib/background/` 안뿐입니다. DOM, 카피, 라우트, 수파베이스는 건드리지 않습니다.

감사 대상: https://builderthon-for-korean-student.vercel.app (1440×900, 390×844, SwiftShader, DOM 표시 상태로 6개 스크롤 지점 캡처).

## 0. 결론 한 줄

폰에서 배경이 달라 보이는 것은 품질을 낮춰서가 아닙니다. **세로 화면에서 수면이 아예 그려지지 않고 있습니다.** 셰이더의 `portrait` 분기가 물, 지평선 빛, 반사 기둥, 나루 점, 파문 링을 전부 끄고 있어서, 폰에 남는 것은 하늘 그라데이션과 등불 하나뿐입니다.

## 1. 실측

세로 10등분 밴드의 평균 휘도입니다(0~255).

| 화면 | 위 → 아래 밴드 평균 휘도 | 세로 대비 |
| --- | --- | --- |
| 데스크톱 히어로 | 8.3 · 13.6 · 36.0 · 48.6 · 42.1 · 55.6 · **80.8** · 47.6 · 21.1 · 19.6 | 9.7배 |
| 폰 히어로 | 19.3 · 31.9 · 27.9 · 36.1 · 34.6 · 29.4 · 31.6 · 32.3 · 24.8 · 30.0 | **1.9배** |

데스크톱은 맨 위가 거의 검정(8.3)이고 7번째 밴드에서 80.8로 솟습니다. 그 봉우리가 지평선과 해입니다. 폰은 19~36 사이에서 평평합니다. 봉우리가 없고, 맨 위도 검정이 되지 않습니다. 화면에서 보이는 그대로 "보라색 판 하나"입니다.

프로그램 챕터(스크롤 22%)에서는 방향이 뒤집힙니다.

| 화면 | 평균 휘도 | 상위 5% 휘도 |
| --- | --- | --- |
| 데스크톱 | 11.7 | 17.9 |
| 폰 | 24.2 | 59.9 |

본문을 읽는 구간에서 **폰 배경이 데스크톱의 두 배로 밝습니다.** 그런데 정작 서울 윤곽은 폰 쪽이 훨씬 약합니다. 배경은 시끄럽고 형상은 안 보이는, 가장 나쁜 조합입니다.

## 2. 원인

### 2.1 가장 큰 것: 세로 화면에서 물이 그려지지 않습니다

`lib/background/shaders/water.ts`의 이 줄입니다.

```glsl
float portrait = 1.0 - step(1.0, uAspect);
...
float mask = max(smoothstep(H - 0.004, H + 0.004, p.y), portrait);
vec3 col = mix(water, sky, mask);
```

`portrait`가 1이면 `mask`가 화면 전체에서 1이 되고, `mix(water, sky, 1.0)`은 `sky`입니다. **`water`가 계산은 되지만 한 픽셀도 쓰이지 않습니다.** 지평선 아래 전체가 `uSkyHorizon` 단색이 되고, 그게 폰에서 보이는 보라색 판입니다.

같은 `portrait`가 세 가지를 더 끕니다.

```glsl
col += uSkyHorizon * exp(-abs(p.y - H) * 130.0) * 0.30 * alive * (1.0 - portrait);  // 지평선 빛
dcol += uGlint * rings * (0.05 + uFlow * 0.045) * (1.0 - portrait);                 // 파문 링
dcol += uLamp * (exp(-rr / 0.009) * 0.42 + exp(-rr / 0.10) * 0.055) * (1.0 - portrait); // 나루 점
```

나루 점은 "배경과 로고가 같은 것을 말하게 하는 유일한 연결선"이라고 같은 파일에 적혀 있습니다. 폰에서는 그 연결선이 없습니다.

### 2.2 왜 그렇게 꺼 두었나

주석에 이유가 남아 있습니다. 2026-09-18 모바일 브리프에서 폰의 링이 "본문 뒤 60~90vw 고리"로 보였고, 반사 기둥이 CTA 버튼 한가운데를 지나갔습니다. 둘 다 실제 문제였습니다.

**다만 진단이 반만 맞았습니다.** 이 셰이더는 가로 거리를 화면 **높이** 단위로 잽니다.

```glsl
float dx = (p.x - lx) * uAspect;
vec2  q  = vec2((p.x - mx) * uAspect, p.y - my);
```

`uAspect`가 데스크톱은 1.6, 폰은 0.46입니다. 그래서 반지름 상수 하나가 데스크톱에서는 화면 가로의 26%를 덮고 폰에서는 91%를 덮습니다. 링과 기둥이 폰에서 거대해 보인 것은 **화면이 좁아서**이지 링과 기둥이 잘못된 것이 아니었습니다. 고칠 자리는 반지름의 기준이고, 켜고 끄는 스위치가 아닙니다.

### 2.3 서울 윤곽이 약한 세 가지 이유가 곱해집니다

| 항목 | 데스크톱 | 폰 | 파일 |
| --- | --- | --- | --- |
| 점 개수 | 1,400 | 500 | `SEOUL_WATERMARK.points` |
| 폭(뷰포트 대비) | 0.58 | 1.10 → 0.90 | `landscapeW` / `portrait.heroW`,`naruW` |
| 형상 밝기 | 1.0 → 0.6 | 0.8 → 0.5 | `edgeBright`,`calmBright` / `portrait.*Bright` |
| 티어 밝기 배수 | 0.85~1.0 | **0.6** | `pickQuality().intensity`, `ParticleField` 211행 |

점은 2.8배 적은데 면적은 2.4배 넓고(0.90 대 0.58, 좁은 화면에서), 밝기는 0.5×0.6 = 0.30 대 0.6×1.0 = 0.60으로 절반입니다. 단위 면적당 잉크로 치면 폰이 데스크톱의 **6분의 1 수준**입니다. 그래서 윤곽이 서울로 읽히지 않고 먼지로 읽힙니다. 게다가 폭 0.90~1.10이면 양옆이 화면 밖으로 잘려서, 남은 점들이 무엇의 일부인지 알 수 없습니다.

### 2.4 블룸이 폰에서 꺼져 있습니다

`pickQuality()`가 `coarse || w < 768 || mem <= 4`에서 `bloom: false`를 돌려줍니다. 해와 물비늘의 번짐이 전부 사라집니다. 이건 성능 판단이었고 근거가 있지만, 지금은 위 세 가지와 합쳐져 "다른 배경"으로 보이게 만드는 마지막 한 겹입니다.

## 3. 고치는 순서

**이 순서대로 하고, 각 단계마다 캡처해서 비교하세요.** 1번만 해도 대부분 해결됩니다. 전부 한 번에 바꾸면 무엇이 대비를 깨뜨렸는지 알 수 없습니다.

### 3.1 [P0] 세로 화면에서도 물을 그립니다

`water.ts`의 `mask`에서 `portrait`를 뺍니다.

```glsl
float mask = smoothstep(H - 0.004, H + 0.004, p.y);
```

지평선 빛의 `(1.0 - portrait)`도 뺍니다.

이 한 줄이 폰 히어로의 평평한 보라판을 없애고, 지평선·물·물비늘·반사 기둥을 되살립니다.

### 3.2 [P0] 화면 가로를 기준으로 하는 보정 계수를 하나 둡니다

껐다 켰다 하는 대신, 좁은 화면에서 반지름을 줄입니다. `portrait` 정의 바로 아래에 둡니다.

```glsl
// 이 셰이더의 가로 거리는 화면 높이 단위입니다(dx에 uAspect를 곱하므로).
// 좁은 화면에서는 같은 반지름이 가로의 훨씬 큰 몫을 덮습니다(1440×900에서
// 26%, 390×844에서 91%). 세로 화면에서 링과 번짐이 거대해 보인 것은 이
// 때문이지 값이 틀려서가 아닙니다. K로 반지름을 나눠 **가로 대비 같은 비율**로
// 맞춥니다. 상한 2.4는 아주 긴 화면에서 점이 사라지지 않게 하는 안전장치입니다.
float K = mix(1.0, clamp(1.0 / max(uAspect, 0.001), 1.0, 2.4), portrait);
```

`K`로 나눌 곳은 넷입니다. 다른 곳에는 쓰지 마세요.

```glsl
sky += uLamp * exp(-length(vec2(dx, (p.y - H) * 1.8)) / (0.075 / K)) * 0.07 * alive; // 등불 번짐
float rings = smoothstep(0.86, 1.0, sin(phase)) * exp(-rr * 2.4 * K);                 // 파문 링
dcol += uLamp * (exp(-rr / 0.009) * 0.42 + exp(-rr / (0.10 / K)) * 0.055);            // 나루 점의 무리
float colW = (0.010 + d * 0.20) * mix(0.62, 1.0, smoothstep(0.75, 1.3, uAspect));     // 기둥 폭은 이미 좁힙니다. 그대로 둡니다.
```

등불의 심(`0.0115`)과 점의 심(`0.009`)은 **건드리지 마세요.** 둘 다 이미 폰에서 10px 안쪽이고, 줄이면 사라집니다.

### 3.3 [P0] 링과 나루 점을 세로 화면에서도 그립니다

3.2를 적용한 뒤에 `(1.0 - portrait)` 두 개를 뺍니다. 3.2 없이 이것만 하면 9/18에 봤던 거대한 고리가 그대로 돌아옵니다. 순서를 지키세요.

### 3.4 [P0] 서울 윤곽을 데스크톱과 같은 구도로

`lib/background/config.ts`:

```ts
  points: { phone: 1100, desktop: 1400 },
  // 세로 화면. 2026-09-19 (사용자: "모바일이 데스크톱을 따라갔으면"). 전에는
  // 1.10 → 0.90이라 양옆이 화면 밖으로 잘렸고, 남은 점이 무엇의 일부인지 알 수
  // 없었습니다. 가로(0.58)보다 조금만 넓게 둡니다. 폰은 화면이 좁아 같은 비율이면
  // 실제 크기가 작아지기 때문입니다. 밝기는 가로와 같은 값으로 올립니다.
  portrait: { heroW: 0.72, heroCy: 0.5, heroBright: 1.0, dissolveVh: 0.4, naruW: 0.72, naruCy: 0.5, naruBright: 0.6 },
```

`heroW`와 `naruW`를 같은 값으로 둔 것이 요점입니다. 지금은 스크롤하면서 형상이 1.10에서 0.90으로 줄어드는데, 가로 화면에는 그런 움직임이 없습니다. 폭이 고정되면 `BackgroundScene`의 세로 분기가 가로와 같은 모양이 됩니다.

### 3.5 [P1] 티어 밝기 배수

`pickQuality()`의 폰 티어 `intensity: 0.6`이 `ParticleField` 211행에서 형상 투명도에 다시 곱해집니다. 3.4에서 밝기를 올린 것이 여기서 반이 깎입니다.

```ts
    return { particles: 900, dprMax: 1.35, bloom: true, intensity: 0.85 };
```

`bloom`도 여기서 켭니다(2.4). `particles`와 `dprMax`는 **그대로 두세요.** 성능이 걸리는 자리는 이 둘이지 블룸이 아닙니다.

### 3.6 [P1] 블룸 세기를 폰에서만 낮춥니다

블룸을 켜되 데스크톱과 같은 세기로 두지 않습니다. `PostFX`의 기본 `intensity: 0.6`을 티어에서 받아 폰에서는 0.42로 둡니다. 생성자에 인자를 하나 더하는 것으로 충분합니다. 기본값은 지금 값이어야 하고, `crossing`과 `field` 변형의 동작이 바뀌면 안 됩니다.

## 4. 절대 하지 말 것

- **`portrait` 분기를 전부 지우지 마세요.** 3.1과 3.3에서 지정한 네 자리만 손댑니다. `lx`의 세로 분기(등불을 가운데로)와 `colW`의 좁히기는 그대로 둡니다. 둘 다 폰에서 실제로 필요합니다.
- **`CameraController`의 fov 75를 60으로 바꾸지 마세요.** `WaterSurface.resize`와 `placeSeoul`이 같은 값을 읽습니다. 한쪽만 바꾸면 수면이 프러스텀보다 작아져 가장자리에 클리어 컬러가 보입니다.
- **밝기 상수를 3.4와 3.5에 적힌 값 위로 올리지 마세요.** 이 배경 위에 본문 흰 글자가 앉습니다. 5장의 대비 검증을 통과하지 못하면 되돌립니다.
- **`particles: 900`과 `dprMax: 1.35`를 올리지 마세요.**
- DOM, 카피, 레이아웃, `data/naru.ts`는 이 브리프의 범위가 아닙니다.

## 5. 검증

각 단계 뒤에 390×844와 1440×900에서 같은 스크롤 지점 여섯을 캡처하고 아래를 재세요. 캡처는 DOM을 보이는 채로 합니다(대비를 같이 보려는 것입니다).

| # | 항목 | 기준 |
| --- | --- | --- |
| 1 | 폰 히어로의 세로 밴드 대비 | 가장 어두운 밴드와 가장 밝은 밴드의 비가 **5배 이상**(지금 1.9배, 데스크톱 9.7배) |
| 2 | 폰 히어로의 맨 위 밴드 휘도 | **12 이하**(지금 19.3, 데스크톱 8.3) |
| 3 | 폰 히어로에 지평선이 보이는가 | 육안으로 가로선 하나와 그 위의 해, 아래로 반사 기둥 |
| 4 | 프로그램 챕터(22%)의 폰 평균 휘도 | **18 이하**(지금 24.2). 데스크톱 11.7보다는 높아도 됩니다 |
| 5 | 서울 윤곽 | 폰에서 좌우가 화면 안에 들어오고, 서울 모양으로 읽힘 |
| 6 | 파문 링의 가로 지름 | 폰에서 뷰포트 가로의 **45% 이하**. 넘으면 3.2의 `K` 상한을 올리세요 |
| 7 | 나루 점 | 폰에서 보이고, 지름이 12px 이하 |
| 8 | 본문 대비 | 폰의 `#december`·`#gains`·`#join` 본문 흰 글자가 배경 대비 **4.5:1 이상**. 가장 밝은 배경 픽셀 기준으로 잽니다 |
| 9 | 데스크톱 | 여섯 지점 전부 이 브리프 적용 전과 **픽셀 차이 없음**. 세로 화면만 바뀌어야 합니다 |
| 10 | 모션 민감 | `prefers-reduced-motion: reduce`에서 폰이 여전히 조용함 |
| 11 | 프레임 | 폰 프로파일에서 초당 프레임이 적용 전보다 20% 넘게 떨어지지 않음. 떨어지면 3.6의 블룸 세기를 먼저 낮추고, 그래도 안 되면 블룸을 되돌립니다 |

**9번이 가장 중요합니다.** 이 작업은 폰을 데스크톱에 맞추는 것이지 둘 다 바꾸는 것이 아닙니다. 데스크톱이 한 픽셀이라도 달라지면 잘못 고친 것입니다.
