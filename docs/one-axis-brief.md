# 레이아웃 브리프: 축을 하나로

대상 레포: `website` (커밋 `48b085e` 기준). 바꾸는 파일은 `components/home/NaruHome.tsx`, 필요하면 `components/home/RecordTabs.tsx`. 카피, 배경, 읽기 판의 모양, `/2026-08`은 건드리지 않습니다. 체인지로그는 `CLAUDE.md` 규칙대로.

## 0. 결론 한 줄

**글의 정렬(왼쪽)과 블록의 위치(가운데)를 나눕니다.** 모든 블록을 화면 가운데 축에 놓고, 그 안의 글은 왼쪽 정렬합니다. 폭은 두 가지만 씁니다.

## 1. 지금 무엇이 뒤섞였나 (1440×900 실측)

가독성 브리프(9월 25일)의 "챕터 머리만 가운데, 그 아래는 왼쪽" 규칙이 **글의 정렬**뿐 아니라 **블록의 위치**까지 왼쪽으로 옮겼습니다(`BODY_AXIS`, 좁은 블록을 `max-w-5xl` 기둥의 왼쪽 끝에 붙임). 브리프가 둘을 구분하지 않았습니다.

그 결과 한 화면에 축이 셋입니다.

| 블록 | 위치 | 왼쪽 끝 x |
| --- | --- | --- |
| 챕터 머리(알약, h2, 리드) | 화면 가운데(720) | 가운데 정렬 |
| 본문 문단, 버튼, 소제목 | 왼쪽에 붙은 672px 기둥 | 144 (오른쪽 600px이 빔) |
| `#gains` 목록 | 가운데에 놓인 넓은 블록 | 216 |
| `#join` 카드 셋, 일정 노선도 | 넓은 기둥 전체 | 144 |

챕터마다 머리는 가운데에 크게 서 있는데, 바로 아래 본문은 왼쪽으로 쏠려 있습니다. 눈이 가운데에서 왼쪽 끝으로 뛰고, 목록이 나오면 다시 조금 안쪽으로 들어옵니다. 배경의 형상도 화면 가운데에 있어서, 왼쪽으로 쏠린 본문은 형상과도 축이 어긋납니다.

폰(390px)은 이미 한 축입니다(본문 왼쪽 끝 모두 27px). **폰은 바뀌지 않아야 합니다.**

## 2. 규칙

```ts
// DECIDED 2026-09-26 (사용자: "어떤 건 left, 어떤 건 central, 뒤죽박죽"): 축은 하나입니다.
// 모든 블록은 화면 가운데 축에 놓고(mx-auto), 글은 그 안에서 왼쪽 정렬합니다.
// 글의 정렬과 블록의 위치는 다른 문제입니다. 9월 25일 BODY_AXIS가 둘을 섞어
// 본문 블록을 넓은 기둥의 왼쪽 끝에 붙였고, 챕터 머리(가운데)와 축이 갈라졌습니다.
// 폭은 둘뿐입니다:
//   READ  = 글을 읽는 기둥. 문단, 소제목, 목록, 버튼, 알림, 숫자 줄, 감사 명단.
//   WIDE  = 셋 이상이 가로로 나란히 서는 것만. 일정 노선도, #join 카드 셋, 세 층 도식.
const READ = "mx-auto w-full max-w-3xl";   // 768px
const WIDE = "mx-auto w-full max-w-5xl";   // 1024px
```

- `BODY_AXIS`를 지우고 쓰던 자리를 전부 `READ`로 바꿉니다.
- 지금 `max-w-2xl`(672px)로 폭을 제한한 본문 블록도 `READ` 안에 두거나 `READ`로 바꿉니다. 한 챕터 안에서 본문 블록의 왼쪽 끝이 하나여야 합니다.
- `#gains` 목록(번호, 제목, 설명의 두 열)은 가로로 셋 이상이 아니므로 `READ`입니다. 안쪽 두 열은 그대로 둡니다.
- 챕터 머리(알약 + h2 + 리드 한 문단)는 지금처럼 가운데 정렬입니다. 리드도 `READ` 폭 안에서 가운데 정렬합니다.
- 챕터 안 소제목과 그 알약(예: "제로백 빌더톤 2026.08 싱가포르" + "8월이 남긴 것")은 `READ`의 왼쪽 끝에 맞춥니다.
- 버튼 줄은 `READ`의 왼쪽 끝에서 시작합니다.
- 컴포넌트 **안쪽**의 열(일정표의 날짜 열, `dl`의 오른쪽 열, `#gains`의 설명 열)은 그대로입니다. 바깥 왼쪽 끝만 맞춥니다.
- 읽기 판은 본문 기둥을 따라가야 합니다. 판이 `BODY_AXIS` 기둥 기준으로 잡혀 있으면 `READ`/`WIDE` 기준으로 옮깁니다. 판의 모양(투명도, 흐림, 가장자리)은 그대로.
- 히어로와 푸터, 카운트다운은 이번 범위가 아닙니다.

## 4. 검증

| # | 항목 | 기준 |
| --- | --- | --- |
| 1 | 축 | 1440×900에서 `main`의 모든 블록(히어로, 푸터 제외) 바깥 상자의 가운데 x가 **720 ± 4** |
| 2 | 왼쪽 끝 | 챕터 안 왼쪽 정렬 글의 바깥 상자 왼쪽 끝이 `READ` 왼쪽 끝(약 336) 또는 `WIDE` 왼쪽 끝(약 208) 둘 중 하나. 그 밖의 값 **0곳**(컴포넌트 안쪽 열 제외) |
| 3 | 폭 종류 | 본문 블록의 `max-w` 값이 `max-w-3xl`, `max-w-5xl` 둘뿐(히어로, 푸터 제외) |
| 4 | 폰 불변 | 390×844 홈 전체 캡처가 적용 전과 같음(픽셀 차이 평균 1/255 이하) |
| 5 | 중간 폭 | 1024×768, 1280×800에서도 1, 2가 성립 |
| 6 | 읽기 판 | 판이 본문 기둥 뒤에 있고, 판 밖으로 글이 나가지 않음 |

측정은 각 블록의 `getBoundingClientRect()`로 합니다. 적용 전후 1440×900 스크린숏을 챕터별로(4장) 나란히 보여 주세요.
